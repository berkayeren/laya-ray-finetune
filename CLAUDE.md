# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Fine-tunes and evaluates the Laya `laya-multilingual` model on the Turkish banking split of Multi3NLU++ (multi-label intent detection, 48 tags), using Ray Train for distributed (DDP) training and Ray Data for distributed inference, against a fine-tuned BERTurk baseline trained with the HF Trainer (`berturk_train.py`, Phase 6), with calibration, abstention, false-positive and latency metrics defined and exercised on val (Phase 7: `report.py --confidence`, `latency.py`). Phase 8 froze the decision rule and the few-shot protocol in the hash-pinned `protocol.json` (`pilot/protocol.py`), scored each final seed once on test and HOTELS behind `score.py`'s protocol gate, and computed the mechanical GO block (`pilot/verdict.py`, `report.py --verdict`, `results/final/`). Phase 9 ran the frozen few-shot protocol unchanged: label-masked bases and continued runs of both models (`--fewshot-base`, `--fewshot-draw`/`--fewshot-k` of `ray_train.py` and `berturk_train.py`), each few-shot checkpoint scored once on test behind the same gate (the committed allow-list `results/fewshot/runs.json`), the few-shot results record `results/fewshot/fewshot.json` (`pilot/fewshot_report.py`, `make fewshot-reports`) and criterion (d)'s few-shot path in the verdict (`report.py --verdict --fewshot`); the recommendation is Phase 10. Dependencies are pinned in `pyproject.toml` and hash-locked in `requirements.txt` (Python 3.12, binary wheels only); `make env` installs them into `.venv`. There is no linter. The scripts are run directly.

## Architecture

- **Task framing:** each of the 48 intent tags in `intents.py` (`INTENTS`) becomes one Laya `noul` (yes/no) question, so one forward pass gives a probability per tag. `QUESTIONS` is defined only in `intents.py` and imported by `pilot/data.py` and `score.py` (a test fails on a second definition). If you change tag wording, regenerate the data and re-run the baselines, because the question text is the model input; `data/splits.json` records `questions_sha256`, so a wording change without a refreeze fails `make test`.
- **Splits:** `make data` writes five outputs to `data/splits/`: `selection_train` (folds 0–13, 1,450 msgs), `val` (14–15, 208), `final_train` (0–15, 1,658), `test` (16–19, 413) and `hotels_probe` (HOTELS 0–19, 1,009, out-of-domain; only the 22 `ood_scoring_tags` are valid gold). Every row labels all 48 tags; no-intent messages are kept by default (`--no-include-no-intent` to another `--out`; consumers read that variant with `--manifest OTHER_DIR/splits.json`, which may not change any split's role, path or folds versus `pilot.data.SPLITS`; outputs record `manifest_is_committed`). The committed `data/splits.json` registers each file's path, role and sha256. `pilot.data.verify_split_file` is the only verifier and hard-fails on a tampered, unregistered or wrong-role file; there is no override (regenerate with `make data`, or deliberately refreeze with `prepare_data.py --rewrite-manifest`, which invalidates downstream results). Duplicate uids hard-fail at prepare time.
- **JSONL schema:** `{"state": text, "uid", "questions": {tag: {"type": "noul", "instructions": ...}}, "expected": {tag: bool}}`. This is Laya's training format. Gold labels come from `expected` (`pilot.dumps.read_gold`); dumps never hold `state`.
- **`pilot/`:** `pins.py` (every pinned revision and sha256: dataset, 40 raw folds, Laya, BERTurk, OOD tag subset), `data.py` (split producer + `verify_split_file`), `audit.py` (report-only duplicate audit to `data/audit/`, hash-registered in the manifest, never changes splits), `weights.py` (`fetch(pin)` downloads only the pinned safetensors files at the full commit SHA and checks their sha256; `make weights`; `identity(dir)` of a local checkpoint hashes the weights, `rl_agent_config.json` and every file under `tokenizer/` and `encoder/` (`files_sha256`), with `tokenizer/tokenizer_config.json`, which `laya.load` rewrites on the first load, bound by its normalized JSON (`NORMALIZED_KEY`, a mirror of laya's rewrite that `tests/test_laya_adapter.py` checks against laya); `checkpoint_digests` + `verify_files` check every one of them before a load; `checkpoint_digests` refuses a local checkpoint without `tokenizer/tokenizer_config.json` or `encoder/config.json` (`dumps.LOCAL_REQUIRED_FILES`), which laya would read unpinned from the Hub; `check_tokenizer_config_rewritable` refuses, on the driver before any load or `ray.init` (`score.resolve_checkpoint`; `ray_train.main` right after `checkpoint_digests`, before `--print-run-id`), a `tokenizer_config.json` laya would have to rewrite in a read-only `tokenizer/` or that is not a JSON object; `check_tokenizer_config_rewritten` is the backstop, right after `laya.load` in `score.load_agent` and `la.load_checkpoint` in `ray_train.py`'s worker, for a file laya could not rewrite anyway (it only warns)), `dumps.py` (the logit dump format: `write_dump` and `load_dump`, the only reader, which hard-fails on any npz, hash, split, question or tag-order mismatch; `read_gold`; `run_id`; `READ_ROLES` = `EVAL_ROLES` (val, test) + `ood_probe`, so `load_dump` and `read_gold` read a hotels_probe dump with every check (Phase 7; since Phase 8 `score.py` writes one for laya or berturk only, a fine-tuned checkpoint only through its protocol gate); an unreadable npz is refused in one line, never a traceback; `gold_valid_tags(entry, manifest)`: all 48 tags for a banking split, the manifest's `ood_scoring_tags` (22, == `pins.OOD_SCORING_TAGS` under the committed manifest) for hotels_probe, in `INTENTS` order), `metrics.py` (torch-free metrics on [n, 48] arrays shared by every system: micro/macro-F1, exact match, top-1, per-tag F1 with support, the val θ rule `select_theta`, `seed_average` and `paired_bootstrap`; Phase 7, on gold Y and probabilities P [n, 48], never logits, so seed-averaged P use the same code: calibration (EVAL-03) `ece_bins`, `brier` (mean over (message, tag) pairs), `nll` (P clipped to `NLL_EPS` 1e-12), `classwise_ece` (`ECE_BINS` 15 equal-width bins, mean over all 48 tags, zero-support included), `reliability`, `calibration`, rule texts `CALIBRATION_RULES`; abstention (EVAL-04) `message_confidence(P, θ)` (the one rule, the joint decision probability: sum of log q, q = p if p >= θ else 1 - p; `CONFIDENCE_RULE`) and `selective` (precision and exact-match accuracy at `COVERAGES` 50/70/80/90 with the integer cut (c * n + 99) // 100 and stable ties, `n_tied_at_cut`, AURC; `COVERAGE_RULE`, `AURC_RULE`); false positives (EVAL-05) `wilson(k, n)` (95% Wilson score, `WILSON_Z`, math only) and `fp_rate(Y, P, θ, cols=None)` (the one rule for the no-intent rate, all 48 columns, and the out-of-domain rate, the 22 banking-only columns; `FP_RULE`); Phase 8: `paired_bootstrap_extra` (Brier, classwise ECE and precision at a coverage on the same `bootstrap_weights` draw as `paired_bootstrap`; `replicate_extra`, `BOOT_EXTRA_RULE`), `average_precision` and `new_tag_ap` (sklearn semantics, a tag with no positive refused, `AP_RULE`; the Phase 9 primary metric) and the θ grids `GRID`/`GRID_CENTI` read-only; it names no system), `laya_adapter.py` (the only module that touches Laya's private API, pinned to laya 0.4.6; `tests/test_laya_adapter.py` checks the version and every wrapped signature, runs a tiny-model round trip, and an AST guard fails on a private laya import anywhere else; Phase 9: `items_per_question`, the masking proof's count of laya training items per question, the only reader of laya's item layout outside laya), `spike.py` (torch-free spike logic for `mps_spike.py`: grid and protocol constants, worker env, neg8 sampling, padding, timing summary, swap readers, verdict and report builders; it must never import torch), `runs.py` (torch-free run-record schema of `ray_train.py`: `EPOCH_FIELDS`, `SEGMENT_FIELDS`, `read_record`; the run identity `IDENTITY`/`NOT_IDENTITY`/`DROPPED_WHEN_NONE`, `canonical`, `run_id`, `check_state`; `neg_items`, the item count without a tokenizer; the LAYA-03 ladder `SPIKE_START`, `RUNG_NEXT`, `rung_label`, `rung_flags`, `oom_message`, `failure_line`; `disk_need_bytes`), `compute.py` (torch-free compute-checkpoint logic: `spike_start`, `split_counts`, `epoch_registered`, `attempt_chain`, `resume_summary`, `measured_from_checkpoint`, `run_overhead` (the probe child's wall clock minus its record's terms, added once per Laya run), `project` (s/step = the largest measured `train_s / optimizer_steps`; every line names its basis and source; the committed-CPU scoring fallback is basis `measured (cpu, wall)`; Ray's per-epoch persist is charged per epoch through `save_s`, the probe child's residual `run_overhead_s` once per run, and the scoring probe's `run_overhead_s` (its wall clock minus its inference seconds) once per Laya `score.py` run; a report from before a term was measured leaves it out and `assumptions` discloses it), `what_if`, `disk_budget`, `assumptions`, `build_report`, `render_markdown`, `write_report`; the provisional experiment matrix `MATRIX`; Phase 9: `fewshot_projection` (the frozen few-shot protocol projected on the committed compute rates, basis measured, `calib_s` None) and `fewshot_decision` (the frozen compute-fallback trigger applied exactly: fallback when the projection exceeds `pilot.fewshot.FALLBACK_HOURS` or on a recorded LAYA-03 ladder failure)), `postfit.py` (torch-free Phase 5 postfit, LAYA-05/LAYA-08: `candidate` reads one run dir's full val dump only and refuses a file path, a test dump in the dir, a `--n` subset, a candidate trained on another split than `selection_train`, a calibrated one or a shipped T other than 1; `fit_temperature` fits one noul T over every val (message, tag) pair over log T in [0.5, 5.0] (`T_MIN`, `T_MAX`, laya's clamp band; scipy's bounded minimiser, a bound wins an exact tie), with laya's `fit_temperature_map` as the test oracle only (within 2e-3); θ by `metrics.select_theta` for the shipped (after T) and raw (T = 1) variants; `select` takes the highest exact `score` (2TP / (2TP + FP + FN) of the summed counts, `OBJECTIVE`), ties to fewer epochs then the lower encoder LR (`TIE_ORDER`), and refuses anything but one full grid of one system and recipe; `protocol(kind)` is the grid of a system kind (laya: `LR_GRID` (2e-05,), the user's single-LR decision of 2026-10-15, fixed, not tuned; `HEAD_LR` 0.0001, `EPOCHS` 4, seed 0, final seeds 0, 1, 2; berturk: `pilot.berturk.PROTOCOL`, the same LR grid, head LR and seeds, epochs 1..30; `head_lr` None, each candidate's head LR tied to its encoder LR, only in the superseded first BERTurk protocol, which `select` still accepts so that record reproduces; `rules.epoch_transfer` names the kind's own schedule, `EPOCH_TRANSFER_TEMPLATE`; `fit` with no grid takes the protocol of its candidates' one system kind, mixed kinds refused); `build_record`/`fit`/`record_bytes`/`write_record`/`read_record` give the record `postfit/1` (ids, digests and numbers only, rebuilds byte for byte in any argument order); `prune_export` deletes an epoch export only after a verified full val dump of exactly that export exists; `check_final`, `final_block`, `final_command` and `final_manifest` (`postfit-final/1`) bind the final seeds to the record; `render_markdown` renders the README Phase 5 block from a Laya record and its final manifest, with the count of candidates whose global θ sits on a θ-grid edge (`theta_edges`; while a shipped θ does, the epoch is never called a plain interior optimum: 05-REVIEW CR-01, rule kept and disclosed by the user's decision)), `berturk.py` (torch-free BERTurk bookkeeping, Phase 6, BASE-01/02/03; never imports torch, transformers, accelerate, Ray or laya: the recipe constants (`LR` 2e-05, `HEAD_LR` = `postfit.HEAD_LR` 1e-4, `HEAD_PREFIX` `classifier.`, `EPOCHS` 30, batch 32, max_len 128, linear schedule, 10% warm-up, AdamW `adamw_torch`, weight decay 0.01, masked BCE); the run identity `IDENTITY`/`NOT_IDENTITY`/`RESOLVED`/`DROPPED_WHEN_NONE`, `canonical`, `run_id` (`berturk-<split>-s<seed>-<8 hex>`); `optimizer_groups` (four AdamW groups, encoder and head each split by the Trainer's weight-decay rule, refused unless the head is exactly the newly initialised parameters); labels in `INTENTS` order (`id2label`, `label2id`, `label_vector`, `check_label_order`, `check_cased`); the checkpoint identity (`identity`, `require_files`, `CHECKPOINT_FILES`: model.safetensors, config.json, vocab.txt, tokenizer_config.json, berturk_train.json) and `dump_run_id` (`berturk-<model[:12]>-<record[:8]>-<files digest[:8]>`); `read_record` (schema `berturk-train/1`) and `training_block` (the sidecar keys pilot.postfit reads); `PROTOCOL` (`lr_grid` (2e-05,), `head_lr` `HEAD_LR`, `epochs` `EPOCHS`, Laya's seeds); `prune_export`; the BASE-03 reference check (`reference_check`, schema `berturk-reference/1`: the chosen candidate's exact val micro-F1 fraction against `THRESHOLD` 707/1000, status ok or investigate, the quoted `REFERENCE`, `DIFFERENCES` and `CAVEATS`, a resolution only on investigate) and `check_reference_for_final` (no final seed unless the check is of that record, equals `reference_check` recomputed from the record (06-REVIEW WR-01) and reads ok or carries a resolution); `final_command`, `final_manifest` (`postfit-final/1`; for a record on the committed manifest a final seed's provenance manifest must be the committed one, 06-REVIEW IN-06); `SUPERSEDED`, the ordered chain (oldest gate first) of the two discarded selection runs, each with its pinned `postfit_sha256`, literal protocol, gate reply verbatim, change sentence and `delta` (the one canonical change of the run that replaced it: `{"head_lr": 0.0001}`, then `{"epochs": 30}`); - **`ray_train.py`:** `laya-train` is single-device, so this script re-implements the training loop inside `TorchTrainer.train_loop_per_worker` using Laya internals (`load_checkpoint`, `items_from_rows`, `encode_item`, `_forward`, `rlcd_loss`/`soft_ce_loss`, `save_checkpoint`; no calibration helper), reached only through `pilot/laya_adapter.py` (`from pilot import laya_adapter as la`). When the lock moves `laya`, `tests/test_laya_adapter.py` fails first; fix the adapter, not the callers. `--data` must be a registered split with role `train` (verified before `ray.init`) that holds no committed held-out content (`pilot.data.refuse_held_out`, shared with `berturk_train.py`: no committed test content in any train split and no committed val content in `selection_train`, keyed on the sha256, uids_sha256 or (uid, message) pairs as the score.py interlock, so a manifest copy cannot relabel val or test as a train split; 06-REVIEW WR-02); `--base multilingual` resolves the pinned weights via `pilot.weights.fetch`, any other value must be a local checkpoint dir. A base whose `tokenizer_config.json` laya would have to rewrite in a read-only `tokenizer/` is refused before `ray.init` too (`pilot.weights.check_tokenizer_config_rewritable`), and a worker's refusal (a `SystemExit` in `train_loop_per_worker`) reaches the console as is (`worker_refusal` in `fit_or_exit`), never as "rerun the same command to resume". Key invariants:
  - Every message the `--max-messages` subsample selects (all of them without it) trains: there is no calibration holdout (LAYA-05: the temperature comes only from val, fitted after training by `postfit.py`). Every rank builds identical items from the same seed, then takes an **equal-sized** shard (the remainder is dropped) so DDP collectives stay in step.
  - Gradient accumulation uses `model.no_sync()` on non-step micro-batches.
  - Every rank attaches a checkpoint to each epoch's `ray.train.report`: its own `rng-rank<r>.pt`, plus rank 0's `train_state.pt` (fp32 train state) and `save.json`; `load_resume` reads every rank's RNG file, so dropping the non-zero ranks' checkpoints breaks every multi-worker resume. Intermediate epoch checkpoints are train states, never laya checkpoints; rank 0 writes each epoch's uncalibrated laya export to `exports/epoch-NNN`, outside the rotation (its embedded run record is a pre-save snapshot: it lists itself, and this epoch's `save_s`, `train_state_bytes` and `export_bytes` are None) (a rerun drops exports past the epoch it resumes from, and refuses to train when one cannot be deleted). The final checkpoint (rank 0, carrying `final.json`) is a laya checkpoint too; it and every export ship T [1, 1, 1] with an empty `temperature_by_options` and `training.calibrated` false, uncalibrated, reset explicitly even from a calibrated base (a base's fitted T never leaks), unless `--postfit` stamps the val-fitted T. The driver copies `result.checkpoint` to `--out`. The output loads with `laya.load(path)`.
  - The script does not fit a temperature, abstention thresholds or produce `laya-train`'s before/after report. T and θ come from `postfit.py` on val; held-out metrics come from `score.py` + `report.py`.
  - **Final seeds (Phase 5, LAYA-08):** `--stop-after-epoch K` (1..`--epochs` - 1) trains epochs 1..K of the `--epochs` schedule and publishes epoch K; the cosine T_max and the sigma anneal keep `--epochs`, so epoch K is the selection run's epoch K. `--postfit RECORD` reads the record before any fetch and, once the base identity is known, refuses before `--print-run-id` and `ray.init` unless `pilot.postfit.check_final` passes (the record's final split, one of its final seeds, the chosen stop epoch, every other canonical value equal to the chosen selection run's, naming the first differing key). The final config then serves the record's T (`temperature` [1, 1, T], `temperature_by_options` {}, `training.calibrated` true, `training.postfit` with the record's sha256, chosen settings, T and θ) and the run record carries `postfit` {sha256, chosen, temperature}. `postfit.py --print-final-commands` prints each command.
  - **Devices (Phase 4):** `--device cpu|cuda|mps` (default cpu; `--gpu` is an alias for `--device cuda`). On every device the worker refuses to train unless every parameter landed on the requested device (`require_param_device`). Ray has no MPS device manager, so `--device mps` needs `--workers 1`: one worker with `use_gpu=False` on an explicit `torch.device("mps")`, with the spike's worker env (`PYTORCH_ENABLE_MPS_FALLBACK=0`, HIGH and LOW watermark ratios 1.0) passed through `ray.init(runtime_env)` and checked in the worker (`check_env`); AdamW runs with `foreach=False, fused=False` there. Gradient checkpointing (encoder and head) is on for every full-encoder run on every device (`--no-grad-checkpointing` turns it off), independent of `--amp`, which defaults on only on cuda and is refused on mps and cpu.
  - **Items:** `--neg K` (default 8; 0 = all 48 labels, data_full) keeps every positive plus K random negatives per training message (`spike.neg8_rows`, seeded by `--neg-seed`, default `--seed`), one draw per run over every selected message.
  - **Fallback ladder (LAYA-03):** every run starts from the spike's config (`pilot.runs.SPIKE_START`: micro-batch 8, max_len 128, grad-accum 4, full encoder). The fallbacks are flags, never an in-process retry: `--freeze-embeddings` (rung `embeddings_frozen`), then also `--micro-batch 4 --grad-accum 8` (`embeddings_frozen+smaller_batch`), then `--freeze-encoder` (`encoder_frozen`, head-only, weaker). The record carries the rung, `fallback` and `weaker`, and an MPS out-of-memory error ends the run with one line naming the epoch and micro-batch (or the stage outside the training step: model move, resume, checkpoint save), the rung and the flags of the next rung; the driver never answers an MPS OOM with "rerun to resume". The exception is an OOM after the last epoch (the final save, `pilot.runs.STAGE_FINAL_SAVE`; `pilot.runs.RESUME_STAGES`): every epoch is saved and a rung flag would change the run id, so that line says to rerun the same command, and `compute_checkpoint.py` ends its chain as failed instead of walking the ladder. That rerun resumes a train state that already holds the last epoch: it never loads the optimizer, scheduler or scaler state (`restore_optimizer`), an OOM while it moves the model to write the final checkpoint is a resume stage too (`pilot.runs.STAGE_FINALIZE_MOVE`), and every run empties the MPS cache after freeing the optimizer, before the final save.
  - **Run identity and resume (LAYA-04):** the run id is `pilot.runs.run_id` of the canonical config (`pilot.runs.IDENTITY`: split, data and base digests, laya version, the resolved device and precision choices, every hyperparameter and the seeds; never a path or a resource), e.g. `laya-selection_train-neg8-s0-1a2b3c4d`. Before `ray.init` the driver refuses when free disk under `--storage` is below `pilot.runs.disk_need_bytes`.

The optimizer is four AdamW param groups (`pilot.berturk.optimizer_groups`): the encoder at `--lr` (default 2e-05) and the fresh classifier head at `--head-lr` (default 1e-4, Laya's head LR: the first BASE-03 fix), each split by the Trainer's weight-decay rule, handed over as `Trainer(optimizers=(optimizer, None))` so the Trainer still builds the linear schedule and its 10% warm-up over both LRs. `--epochs` defaults to 30 (the second BASE-03 fix); batch 32, max_len 128, fp32, no gradient checkpointing, `transformers.set_seed` right before the head is created. Every epoch writes an export `<storage>/<run_id>/exports/epoch-NNN` with exactly the five `CHECKPOINT_FILES` (tokenizer files copied byte for byte) and `berturk_train.json` (`berturk-train/1`: run id, canonical config, epoch, schedule, calibrated false, T 1.0, the run record with `optimizer_groups`, per-epoch rows, peaks and swap, code state). The run id is `pilot.berturk.run_id` of the canonical config; A6 no resume: an existing run dir is refused, a run is rerun from scratch (`--print-run-id` prints the id). Final seeds: `--stop-after-epoch K` trains epochs 1..K of the `--epochs` schedule; `--postfit RECORD --reference REF --out DIR` refuses, before any fetch or run dir, unless REF is the record's BASE-03 check reading ok or resolved (`check_reference_for_final`) and every setting is the chosen run's (`pilot.postfit.check_final`), and stamps the record's T (calibrated true, `postfit = final_block`). Storage defaults to `berturk_runs/` (gitignored as `/berturk_runs/`); it refuses below `pilot.berturk.disk_need_bytes` free. Few-shot (Phase 9, FEW-01, FEW-02): the same two modes as `ray_train.py`, bound the same way before any fetch, load or run dir (`require_frozen`, `read_mode`, `check_source`; the frozen `rules.base_runs.berturk` must name `pilot.berturk.MASK_LABEL` and float32). `--fewshot-base` trains a label-masked base: every message is kept and the held-out columns are `MASK_LABEL` in every label vector, so the masked BCE gives them zero gradient (the run refuses to train when any label of those columns is not masked; `check_base` binds it to `rules.base_runs.berturk` and the chosen selection run). `--fewshot-draw D --fewshot-k K --base <masked base>` continues a masked base from its own fine-tuned head on the frozen support plus replay rows in `selection_train` file order (`pilot.fewshot.berturk_rows`: a support row keeps all 48 labels, a replay row masks the held-out tags; `check_continued`; no `--stop-after-epoch`); `from_pretrained` must report no missing, unexpected or mismatched key, and `pilot.berturk.optimizer_groups(..., continued=True)` requires that nothing was newly initialised (no fresh head, no weight imprinting: XCMP-04 is v2), the encoder at `--lr` and the head at `--head-lr` under the linear schedule over the continued epochs. Both modes refuse `--postfit`, `--reference` and `--max-messages`; `fewshot` is an `IDENTITY` key in `DROPPED_WHEN_NONE` and the `--fewshot-*` flags are `NOT_IDENTITY`, so every committed run id is unchanged; the run record's `fewshot` entry is the masking proof (counts, tags and digests, never a uid).
- **`score.py`:** the only place a model runs. It turns one system on one split into `results/dumps/RUN_ID/SPLIT.npz` (float32 logits [n, 48] in `INTENTS` order + uids, no text) and a JSON sidecar (split and manifest hashes, system identity, temperature, run id). Scoring is fp32 on every device: laya 0.4.6 autocasts to fp16 on mps and cuda, so `la.force_fp32` turns autocast off after the load, the sidecar records laya's load-time default (`laya_default_amp`, `laya_default_dtype`), and `check_agent` refuses another device, a non-fp32 dtype, autocast on or a GPU-to-CPU fallback, after every batch too. `--device cpu|mps|cuda` (default cuda when `--gpus-per-worker > 0`, else cpu); mps scores in-process only (`--workers 0`). `--workers 0` scores in-process, `--workers N` with N Ray Data `Predictor` actors (`score.Predictor`, the only class; one checkpoint load each, `--cpus-per-worker` CPUs and torch threads, rows reassembled by uid into split-file order; Ray Data's default actor fault tolerance stays on, so an actor killed mid-split (OOM killer, crash) is restarted and its batch retried; Ray restarts an actor whose worker exits forever, a `SystemExit` included, so inside Ray the `Predictor` re-raises a refusal from its constructor or a batch as a plain `RuntimeError` marked `score.REFUSAL`, which Ray never retries, and the driver ends the run with the refusal's own one line and no dump). `--model majority|prior` are baselines from the matching training split, never the scored labels (`final_train` for `test`, `selection_train` for `val`), stored as clipped logits with T = 1. `--n N` scores a seed-0 shuffled subset for debugging only, never under `results/dumps`. An existing `<run_id>/<split>` dump is refused before any load unless `--force` (`make baselines` passes it); a dump outside the repo prints its absolute path. A fine-tuned checkpoint's sidecar records its `seed` and a `training` block (train run id, split, encoder LR, epoch and schedule, rung, calibrated, the postfit sha256, the canonical run config and `config_sha256_sans_seed`, `pilot.dumps.training_digest`, shared by the seeds of one recipe and epoch). **The protocol gate (Phase 8, REP-01)** replaced the Phase 5 Laya and Phase 6 BERTurk test interlocks (`refuse_finetuned_test`, `refuse_berturk_test`). `gate_trigger` keys on the content they keyed on, extended to HOTELS, over every parsed row before `--n`: every local Laya checkpoint (any `--checkpoint` but the pinned `multilingual`, keyed on the identity, never on the checkpoint's own `fine_tuned` or `training.ray_train` claim, 08-REVIEW WR-02; the repository rule of `tests/test_results.py`'s `_finetuned`) on a split with role test or ood_probe (`GATED_ROLES`) under the committed manifest, any BERTurk checkpoint on such a split under any manifest, and either on a split of any role and manifest whose sha256 or uids_sha256 is the committed test or hotels_probe entry's, or that holds any (uid, message) pair of the committed `test.jsonl` or `hotels_probe.jsonl` (`pilot.data.holds_committed`; 05-REVIEW CR-02, 06-REVIEW CR-01); a uid alone is not the key, so the synthetic CPU smoke test stays outside it. That content check fails closed like report.py's (`pilot.data.require_committed_files`, 08-REVIEW WR-01): under a non-committed manifest of the pinned dataset the trigger refuses while the committed `test.jsonl` or `hotels_probe.jsonl` is missing. A triggered run is refused before any checkpoint hashing, fetch, model load or Ray start (`protocol_gate`) unless `pilot.protocol.require_frozen` passes, there is no `--n`, no `--force` and no `--out-root` other than results/dumps, the manifest is the committed one and `pilot.protocol.gated_split` names the split, and `--device`/`--workers` are the protocol's scoring block (mps, 0); after the identity is hashed, and before any file is parsed or a model loads, the dump run id must be admitted (`require_admitted`): one of that system's final seeds (`pilot.protocol.final_seed_allowed`), on test or HOTELS, or (Phase 9) a few-shot checkpoint of that system listed in the committed allow-list `results/fewshot/runs.json` (`pilot.fewshot.admitted`, which reads it and runs `pilot.fewshot.check_runs` at every call: this pin, the recorded mode, the frozen draws and base pairing, the masking proofs), on test only (the frozen `fewshot.rules.test_admission`; HOTELS is never opened for it); an unlisted, retrained or edited few-shot checkpoint is refused naming its dump run id. Once means once: an existing gated dump is refused, and so is an npz an interrupted gated run left without its sidecar (the orphan rule: delete it and rerun the one command). An admitted dump's sidecar carries `protocol_sha256`, and an admitted few-shot dump's also `fewshot_runs_sha256` (the sha256 of the runs manifest that listed it); every other dump (a masked base's val dump included: its ungated θ source) has no such key. Every gate refusal is one line starting with `GATE` (`"protocol gate (Phase 8): "`) naming the checkpoint, the split, the trigger and the fix. `--model berturk --checkpoint DIR` (Phase 6) scores a `berturk_train.py` export or final seed in-process only (`--workers 0`), fp32 on cpu, mps or cuda (`check_bert` refuses float16, another device or autocast, after the load and every batch); every BERTurk checkpoint is fine-tuned, so on test or HOTELS it goes through the protocol gate above before the checkpoint is hashed; it refuses a checkpoint missing a `CHECKPOINT_FILES` entry, a config.json that does not score `INTENTS` in order (`check_label_order`) and a lowercasing tokenizer (`check_cased`); the dump run id is `pilot.berturk.dump_run_id`, the logits are the classifier logits, the shipped T is `berturk_train.json`'s and the sidecar's training block comes from `pilot.berturk.training_block`; `report.binds_every_file` accepts a complete BERTurk identity, so a moved checkpoint stays the same source. `score.load_bert(checkpoint, ident, device, threads)` is the one BERTurk loader (every digest verified right before the fp32 load, `check_bert`), shared by `score_berturk` and `latency.py`, so the timed checkpoint is loaded exactly as it is scored.
- **`report.py`:** numpy only (no torch, Ray, laya or model). `report.py RUN_DIR [--split test]` recomputes every metric from verified dumps: two temperature variants (`shipped`, the headline, and `raw`, T = 1), each with a row at θ 0.5 and at the val-selected θ (global θ on val micro-F1 over 0.05..0.95 in 0.01 steps; per-tag θ only for tags with 10 or more val positives; ties toward 0.5; chosen on the run dir's full val dump, never on test, and disclosed in full). - **`latency.py`:** the Phase 7 latency harness (EVAL-06), reported, not gated (latency is not a decision criterion; a budget is DEC-01, v2). One run times every final seed of one system (`--system laya|berturk`) listed in its final manifest (`--final-manifest`, default `results/postfit/<system>-final.json`; seeds under `--checkpoint-root`, default the repo root) on one device (`--device cpu|mps|cuda`), in this process, no Ray, at batch 1, through the path that scored the dumps: Laya via `score.resolve_checkpoint`, `la.check_version` and `score.Predictor` (fp32, autocast off; laya's fp16 MPS default is not what is timed), BERTurk via `score.check_berturk` and `score.load_bert`. ## Resource notes

Each Ray worker holds about 2.6 GB. Two CPU workers ran out of memory in a 7 GB sandbox, so plan for 16 GB or more per worker. `ray_train.py` is single-node: workers read the driver-local base weights and split, so it refuses a multi-node Ray cluster. `--freeze-encoder` trains the head only. It fits small machines but gains much less. Disk: about 1.5 GB venv + 1.1 GB weights + a few MB data. BERTurk on MPS peaks at about 6.6 GiB (the 30-epoch selection run; the final seeds at up to 6.3 GiB); run one MPS job at a time. A 30-epoch selection run takes about 10 minutes and its 30 exports need about 12.4 GiB of transient disk (`berturk_train.py` refuses below about 13.4 GiB free); `postfit.py --prune` frees each export once its val dump exists. The Phase 7 latency runs (all four, the six final seeds) take about 23 minutes on the M4, one job at a time on a quiet machine (Laya on CPU alone about 15 minutes).
