# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Fine-tunes and evaluates the Laya `laya-multilingual` model on the Turkish banking split of Multi3NLU++ (multi-label intent detection, 48 tags), using Ray Train for distributed (DDP) training and Ray Data for distributed inference. Dependencies are pinned in `pyproject.toml` and hash-locked in `requirements.txt` (Python 3.12, binary wheels only); `make env` installs them into `.venv`. There is no linter. The scripts are run directly.

## Commands

```bash
# Environment and data (pinned, hash-verified)
make env && source .venv/bin/activate      # python3.12 venv + pip install --require-hashes --only-binary :all:
make data                                  # pinned Multi3NLU++ -> data/splits/*.jsonl, data/audit/, data/splits.json
make test                                  # offline: pytest -m "not mps and not data and not weights" in the ACTIVE interpreter (or: make test PYTHON=.venv/bin/python)
make test-all                              # pytest -m "not mps": adds the pinned dataset + ~1.1 GB weights download tests
make weights                               # optional prefetch of the pinned Laya + BERTurk weights (~1.1 GB)
make lock / make lock-check                # maintainer: regenerate the lock / prove it resolves on all 3 platforms

# Train the full encoder on the Apple GPU (one Ray worker, the Phase 2 spike's start config, neg8 items by default)
python ray_train.py --data data/splits/selection_train.jsonl --base multilingual --out ckpt \
    --device mps --workers 1 --micro-batch 8 --grad-accum 4 --max-len 128
# CUDA: --device cuda --workers N (--gpu is an alias for --device cuda); CPU smoke test (default --device cpu):
python ray_train.py --data data/splits/selection_train.jsonl --base multilingual --out ckpt \
    --workers 2 --freeze-encoder --max-messages 100 --epochs 2
python ray_train.py ... --print-run-id         # the run id (= ray_results/<run_id>/) without starting Ray
# Resume after a kill or crash: rerun the identical command (it resumes from the last epoch-NNN checkpoint)

# Phase 4 compute checkpoint: 2-epoch MPS probe with a kill and resume, BERTurk and scoring probes, matrix projection
caffeinate -i python compute_checkpoint.py --out results/compute   # about 45-55 min on a quiet Mac on AC power

# Score one system on one split into a logit dump (results/dumps/RUN_ID/SPLIT.npz + .json); --workers 0 = in-process
python score.py data/splits/val.jsonl --model laya --checkpoint multilingual --workers 2 --cpus-per-worker 4
python score.py data/splits/val.jsonl --model laya --checkpoint ./ckpt --device mps --workers 0   # fp32 on MPS
python score.py data/splits/test.jsonl --model prior          # or --model majority; --n N = debug subset to a temp dir
# an existing dump is refused; --force rescores it (results/dumps is the committed audit record)
# Dumps -> metrics (numpy only, no model): θ 0.5 and val-selected θ, shipped and raw (T = 1) temperature
python report.py results/dumps/laya-zeroshot-7b928d82 --split test     # add --out PATH to save the JSON
python report.py --compare results/dumps/laya-zeroshot-7b928d82 results/dumps/prior --split test   # paired bootstrap, B = 10,000
python report.py --table results/reports                      # the README results table (markdown)
# One-step wrapper (score.py --model laya, then report.py); --workers 0 runs without Ray; dumps go to a temp dir
python evaluate.py data/splits/test.jsonl --checkpoint ./ckpt --workers 0 --n 20   # --device, --out-root, --force
# Phase 3 baselines: score majority, prior and zero-shot Laya on val + test, then rebuild results/reports/ (about 5 min)
make baselines                                 # needs make data + the pinned weights
make baseline-reports                          # rebuild reports + table from the committed dumps, no model

# Phase 2 MPS feasibility spike (about 20-40 min on a quiet Mac; writes results/spike/mps_spike.json + .md)
# smoke: add --grid 4x128 --warmup-steps 1 --measured-steps 2 --effective-batch 8 --min-available-gib 0 and another --out
python mps_spike.py --out results/spike
```

## Architecture

- **Task framing:** each of the 48 intent tags in `intents.py` (`INTENTS`) becomes one Laya `noul` (yes/no) question, so one forward pass gives a probability per tag. `QUESTIONS` is defined only in `intents.py` and imported by `pilot/data.py` and `score.py` (a test fails on a second definition). If you change tag wording, regenerate the data and re-run the baselines, because the question text is the model input; `data/splits.json` records `questions_sha256`, so a wording change without a refreeze fails `make test`.
- **Splits:** `make data` writes five outputs to `data/splits/`: `selection_train` (folds 0–13, 1,450 msgs), `val` (14–15, 208), `final_train` (0–15, 1,658), `test` (16–19, 413) and `hotels_probe` (HOTELS 0–19, 1,009, out-of-domain; only the 22 `ood_scoring_tags` are valid gold). Every row labels all 48 tags; no-intent messages are kept by default (`--no-include-no-intent` to another `--out`; consumers read that variant with `--manifest OTHER_DIR/splits.json`, which may not change any split's role, path or folds versus `pilot.data.SPLITS`; outputs record `manifest_is_committed`). The committed `data/splits.json` registers each file's path, role and sha256. `pilot.data.verify_split_file` is the only verifier and hard-fails on a tampered, unregistered or wrong-role file; there is no override (regenerate with `make data`, or deliberately refreeze with `prepare_data.py --rewrite-manifest`, which invalidates downstream results). Duplicate uids hard-fail at prepare time.
- **JSONL schema:** `{"state": text, "uid", "questions": {tag: {"type": "noul", "instructions": ...}}, "expected": {tag: bool}}`. This is Laya's training format. Gold labels come from `expected` (`pilot.dumps.read_gold`); dumps never hold `state`.
- **`pilot/`:** `pins.py` (every pinned revision and sha256: dataset, 40 raw folds, Laya, BERTurk, OOD tag subset), `data.py` (split producer + `verify_split_file`), `audit.py` (report-only duplicate audit to `data/audit/`, hash-registered in the manifest, never changes splits), `weights.py` (`fetch(pin)` downloads only the pinned safetensors files at the full commit SHA and checks their sha256; `make weights`), `dumps.py` (the logit dump format: `write_dump` and `load_dump`, the only reader, which hard-fails on any npz, hash, split, question or tag-order mismatch; `read_gold`; `run_id`), `metrics.py` (torch-free metrics on [n, 48] arrays shared by every system: micro/macro-F1, exact match, top-1, per-tag F1 with support, the val θ rule `select_theta`, `seed_average` and `paired_bootstrap`), `laya_adapter.py` (the only module that touches Laya's private API, pinned to laya 0.4.6; `tests/test_laya_adapter.py` checks the version and every wrapped signature, runs a tiny-model round trip, and an AST guard fails on a private laya import anywhere else), `spike.py` (torch-free spike logic for `mps_spike.py`: grid and protocol constants, worker env, neg8 sampling, padding, timing summary, swap readers, verdict and report builders; it must never import torch), `runs.py` (torch-free run-record schema of `ray_train.py`: `EPOCH_FIELDS`, `SEGMENT_FIELDS`, `read_record`; the run identity `IDENTITY`/`NOT_IDENTITY`, `canonical`, `run_id`, `check_state`; `neg_items`, the item count without a tokenizer; the LAYA-03 ladder `SPIKE_START`, `RUNG_NEXT`, `rung_label`, `rung_flags`, `oom_message`, `failure_line`; `disk_need_bytes`), `compute.py` (torch-free compute-checkpoint logic: `spike_start`, `split_counts`, `epoch_registered`, `attempt_chain`, `resume_summary`, `measured_from_checkpoint`, `run_overhead` (the probe child's wall clock minus its record's terms, added once per Laya run), `project` (s/step = the largest measured `train_s / optimizer_steps`; every line names its basis and source; the committed-CPU scoring fallback is basis `measured (cpu, wall)`; Ray's per-epoch persist is charged per epoch through `save_s`, the probe child's residual `run_overhead_s` once per run, and the scoring probe's `run_overhead_s` (its wall clock minus its inference seconds) once per Laya `score.py` run; a report from before a term was measured leaves it out and `assumptions` discloses it), `what_if`, `disk_budget`, `assumptions`, `build_report`, `render_markdown`, `write_report`; the provisional experiment matrix `MATRIX`).
- **`tests/`:** pytest with strict markers `unit` (offline), `data` (pinned dataset download), `weights` (pinned weights), `ray`, `mps`. `make test` = `pytest -m "not mps and not data and not weights"` (offline); `make test-all` = `pytest -m "not mps"`. Guards include installed == lock, single `QUESTIONS` source, no unpinned load calls, split contracts, and repository hygiene (only `data/splits.json` tracked under `data/`, no message text, no local paths; committed dumps hold only float32 logits and uids, no subset dump or report is tracked). Scoring-path tests: `test_metrics.py` and `test_bootstrap.py` (metrics, θ rule, paired bootstrap), `test_score_report.py` (dump contract, role gate, baselines, tamper refusals), `test_score_laya.py` (tiny offline checkpoint), `test_score_ray.py` (`ray`, Ray Data dump == in-process dump), `test_laya_adapter.py` (adapter version, signature and import guard), `test_smoke_cpu.py` (`ray`, EVAL-08: tiny checkpoint -> `ray_train.py` -> `score.py` val + test -> `report.py`; in `make test`, about 25 s), `test_consumers.py` (refusals before any model load or `ray.init`) and `test_results.py` (the README results block equals `report.render_table` of the committed reports, every committed dump verifies, the Makefile run id matches; `data`: every committed report reproduces from the committed dumps). Spike tests: `test_spike_unit.py` (offline logic), `test_spike_ray.py` (`ray`, a 1-worker Ray Train run on CPU with a tiny offline model; in `make test`), `test_spike_mps.py` (`mps`, the tiny model on real MPS; excluded from both make targets, run with `pytest -m mps tests/test_spike_mps.py`) and `test_spike_real.py` (`data`/`weights`). Phase 4 training tests: `test_runs_unit.py` (offline run-record schema, run identity and ladder), `test_ray_train_unit.py` (offline: the worker-side helpers, without Ray or a model), `test_train_ray.py` (`ray`, a full-encoder tiny-checkpoint run on `--device cpu` and its run record), `test_train_resume.py` (`ray`, run id and kill/resume; on CPU the resumed weights are byte-identical to an uninterrupted run), `test_train_mps.py` and `test_score_mps.py` (`mps`, the tiny checkpoint trained and scored on real MPS; the MPS dump is fp32 and matches the CPU dump). Compute-checkpoint tests: `test_compute_unit.py` (offline projection, report and markdown), `test_compute_ray.py` (`ray`, `compute_checkpoint.py` end to end on CPU with the tiny checkpoint and `--interrupt fail`) and `test_compute_report.py` (the committed `results/compute/` report is the complete-protocol MPS run, its projection, what-if, disk budget, assumptions and markdown recompute from its own JSON, and it passes the hygiene check).
- **`ray_train.py`:** `laya-train` is single-device, so this script re-implements the training loop inside `TorchTrainer.train_loop_per_worker` using Laya internals (`items_from_rows`, `split_calibration`, `encode_item`, `_forward`, `rlcd_loss`/`soft_ce_loss`, `calibration_records`, `save_checkpoint`, `fit_temperature_map`), reached only through `pilot/laya_adapter.py` (`from pilot import laya_adapter as la`). When the lock moves `laya`, `tests/test_laya_adapter.py` fails first; fix the adapter, not the callers. `--data` must be a registered split with role `train` (verified before `ray.init`); `--base multilingual` resolves the pinned weights via `pilot.weights.fetch`, any other value must be a local checkpoint dir. Key invariants:
  - Every rank builds identical items and an identical calibration split from the same seed (whole messages are held out for calibration, never single (message, question) items), then takes an **equal-sized** shard (the remainder is dropped) so DDP collectives stay in step.
  - Gradient accumulation uses `model.no_sync()` on non-step micro-batches.
  - Every rank attaches a checkpoint to each epoch's `ray.train.report`: its own `rng-rank<r>.pt`, plus rank 0's `train_state.pt` (fp32 train state) and `save.json`; `load_resume` reads every rank's RNG file, so dropping the non-zero ranks' checkpoints breaks every multi-worker resume. Intermediate epoch checkpoints are train states, never laya checkpoints; rank 0 writes each epoch's uncalibrated laya export to `exports/epoch-NNN`, outside the rotation (its embedded run record is a pre-save snapshot: it lists itself, and this epoch's `save_s`, `train_state_bytes` and `export_bytes` are None) (a rerun drops exports past the epoch it resumes from, and refuses to train when one cannot be deleted). Only the final checkpoint (rank 0, carrying `final.json`) is a calibrated laya checkpoint: after training, rank 0 fits temperature calibration on the held-out messages and writes the final config (`temperature`, `temperature_by_options`, `training.ray_train`). The driver copies `result.checkpoint` to `--out`. The output loads with `laya.load(path)`.
  - The script does not fit abstention thresholds or produce `laya-train`'s before/after report. Held-out metrics come from `score.py` + `report.py`.
  - **Devices (Phase 4):** `--device cpu|cuda|mps` (default cpu; `--gpu` is an alias for `--device cuda`). On every device the worker refuses to train unless every parameter landed on the requested device (`require_param_device`). Ray has no MPS device manager, so `--device mps` needs `--workers 1`: one worker with `use_gpu=False` on an explicit `torch.device("mps")`, with the spike's worker env (`PYTORCH_ENABLE_MPS_FALLBACK=0`, HIGH and LOW watermark ratios 1.0) passed through `ray.init(runtime_env)` and checked in the worker (`check_env`); AdamW runs with `foreach=False, fused=False` there. Gradient checkpointing (encoder and head) is on for every full-encoder run on every device (`--no-grad-checkpointing` turns it off), independent of `--amp`, which defaults on only on cuda and is refused on mps and cpu.
  - **Items:** `--neg K` (default 8; 0 = all 48 labels, data_full) keeps every positive plus K random negatives per training message (`spike.neg8_rows`, seeded by `--neg-seed`, default `--seed`), drawn after the message-level calibration holdout; the calibration messages always keep all 48 labels.
  - **Fallback ladder (LAYA-03):** every run starts from the spike's config (`pilot.runs.SPIKE_START`: micro-batch 8, max_len 128, grad-accum 4, full encoder). The fallbacks are flags, never an in-process retry: `--freeze-embeddings` (rung `embeddings_frozen`), then also `--micro-batch 4 --grad-accum 8` (`embeddings_frozen+smaller_batch`), then `--freeze-encoder` (`encoder_frozen`, head-only, weaker). The record carries the rung, `fallback` and `weaker`, and an MPS out-of-memory error ends the run with one line naming the epoch and micro-batch (or the stage outside the training step: model move, resume, checkpoint save, calibration), the rung and the flags of the next rung; the driver never answers an MPS OOM with "rerun to resume". The exception is an OOM after the last epoch (calibration, final save; `pilot.runs.RESUME_STAGES`): every epoch is saved and a rung flag would change the run id, so that line says to rerun the same command (`--calib-batch` is not in the run id), and `compute_checkpoint.py` ends its chain as failed instead of walking the ladder. That rerun resumes a train state that already holds the last epoch: it never loads the optimizer, scheduler or scaler state (`restore_optimizer`), an OOM while it moves the model is a resume stage too (`pilot.runs.STAGE_RECALIBRATE_MOVE`), and every run empties the MPS cache after freeing the optimizer, before calibrating.
  - **Run identity and resume (LAYA-04):** the run id is `pilot.runs.run_id` of the canonical config (`pilot.runs.IDENTITY`: split, data and base digests, laya version, the resolved device and precision choices, every hyperparameter and the seeds; never a path or a resource), e.g. `laya-selection_train-neg8-s0-1a2b3c4d`. It is the Ray experiment name, so `--storage/<run_id>/` is the run's only directory; `--print-run-id` prints it and exits without starting Ray. Every epoch reports `epoch-NNN` with rank 0's `train_state.pt` (fp32 model, AdamW, scheduler, record so far) and each rank's `rng-rank<r>.pt` (`CheckpointConfig(num_to_keep=1)`, `max_failures=0`); rerunning the identical command after a kill resumes from it through `ray.train.get_checkpoint()` (`weights_only=True` loads; `check_state` refuses another run's state). A finished run's final checkpoint carries `final.json`, so its rerun only copies it to `--out`. Rank 0 also writes each epoch's uncalibrated laya export to `--storage/<run_id>/exports/epoch-NNN` (for Phase 5 epoch selection; `--no-export-epochs` skips them). Before `ray.init` the driver refuses when free disk under `--storage` is below `pilot.runs.disk_need_bytes`.
  - **Run record (LAYA-06):** `training.ray_train.record` in the checkpoint config: device, parameter device, torch threads, worker env (`KEY=VALUE` strings), precision and checkpointing choices, rung, load / calibration / final-save seconds, one row per completed epoch with exactly `pilot.runs.EPOCH_FIELDS` (wall clock, save time (with `save_s_includes_persist`, it includes Ray's persist of the epoch checkpoint, except in the row of the epoch a rerun resumed from), optimizer steps, items, peak memory, swap delta, segment, resumed) and one `SEGMENT_FIELDS` entry per run segment (git sha, dirty flag and uncommitted-diff digest, both over the same files: tracked changes outside `.planning/` plus untracked `*.py`; resume load seconds and peak memory); `code_changed_on_resume` flags (never refuses) segments that ran another HEAD or another uncommitted diff, or ran without git.
- **`score.py`:** the only place a model runs. It turns one system on one split into `results/dumps/RUN_ID/SPLIT.npz` (float32 logits [n, 48] in `INTENTS` order + uids, no text) and a JSON sidecar (split and manifest hashes, system identity, temperature, run id). The input must be a registered split with role `test` or `val` and a matching sha256 (train splits and `hotels_probe` are refused before any model load or `ray.init`). `--model laya` (default; `--checkpoint multilingual` = the pinned, digest-verified weights, run id `laya-zeroshot-7b928d82`, or a local checkpoint dir, run id `laya-<model_sha256[:12]>-<config_sha256[:8]>`, so two checkpoints sharing weights but not configs never share a dump dir) loads through the public `laya.load(..., expected_sha256=...)` and reads the raw noul margins and served temperature through `pilot/laya_adapter.py`. Scoring is fp32 on every device: laya 0.4.6 autocasts to fp16 on mps and cuda, so `la.force_fp32` turns autocast off after the load, the sidecar records laya's load-time default (`laya_default_amp`, `laya_default_dtype`), and `check_agent` refuses another device, a non-fp32 dtype, autocast on or a GPU-to-CPU fallback, after every batch too. `--device cpu|mps|cuda` (default cuda when `--gpus-per-worker > 0`, else cpu); mps scores in-process only (`--workers 0`). `--workers 0` scores in-process, `--workers N` with N Ray Data `Predictor` actors (`score.Predictor`, the only class; one checkpoint load each, `--cpus-per-worker` CPUs and torch threads, rows reassembled by uid into split-file order). `--model majority|prior` are baselines from the matching training split, never the scored labels (`final_train` for `test`, `selection_train` for `val`), stored as clipped logits with T = 1. `--n N` scores a seed-0 shuffled subset for debugging only, never under `results/dumps`. An existing `<run_id>/<split>` dump is refused before any load unless `--force` (`make baselines` passes it); a dump outside the repo prints its absolute path.
- **`report.py`:** numpy only (no torch, Ray, laya or model). `report.py RUN_DIR [--split test]` recomputes every metric from verified dumps: two temperature variants (`shipped`, the headline, and `raw`, T = 1), each with a row at θ 0.5 and at the val-selected θ (global θ on val micro-F1 over 0.05..0.95 in 0.01 steps; per-tag θ only for tags with 10 or more val positives; ties toward 0.5; chosen on the run dir's full val dump, never on test, and disclosed in full). Rows carry micro/macro-F1, exact match, top-1 (over messages with a gold tag; `n_top1`/`n_no_intent`) and per-tag F1 with support. `--compare A_DIRS B_DIRS` is the EVAL-07 paired message-level bootstrap (B = 10,000, seed 0; per-seed probabilities averaged before thresholding; descriptive only). `--table PATH...` renders the markdown results table (`render_table`). θ is applied only to a dump from the same source as its val dump: the two sidecars must agree on `SAME_SOURCE_KEYS` (system kind, checkpoint identity, shipped T, scorer device, dtype and amp; the checkpoint path only when no identity binds the scored bytes, so a renamed checkpoint is still the same source), else the report is refused naming the key. Reports hold no timestamps, so they rebuild byte-for-byte from the dumps.
- **`evaluate.py`:** a thin wrapper kept for the old CLI: it runs `score.py --model laya` and prints `report.run_report` of the dump (no metric or model code of its own; a test enforces that). Without `--out-root` the dump goes to a fresh temp dir (printed), never `results/dumps`; `--device` and `--force` are forwarded to `score.py`.
- **`mps_spike.py`:** the Phase 2 MPS feasibility spike (LAYA-09): does a full-encoder Laya fine-tune fit on the 16 GB M4? The orchestrator imports no torch; it verifies `selection_train`, fetches the pinned weights, runs a quiet-machine preflight (`--min-available-gib`, idle swap growth) and starts one fresh child process per attempt, because torch reads `PYTORCH_ENABLE_MPS_FALLBACK` once at import and the MPS allocator keeps a process-wide high-water mark. Each child runs a 1-worker `TorchTrainer` with `use_gpu=False` (Ray has no MPS device manager) on an explicit `torch.device("mps")`, times padded and real neg8 optimizer steps with gradient checkpointing, and returns `run.json` through a Ray `Checkpoint`. Every config runs strict (`PYTORCH_ENABLE_MPS_FALLBACK=0`) first and is rerun with fallback 1 only if an op is not implemented (the op inventory); a swap-growing attempt gets one rerun and a rung-none memory failure retries with `tok_embeddings` frozen (rung `embeddings_frozen`; a frozen encoder never FITS). After the verdict the chosen config reruns in-process without Ray to report Ray's overhead. It reaches the Laya internals listed in its docstring (`LAYA_INTERNALS`, the names the committed report records) through `pilot/laya_adapter.py`, whose `COVERS` maps each one to an adapter function.
- **`compute_checkpoint.py`:** the Phase 4 compute checkpoint (LAYA-07): measures a real Laya fine-tune from the spike's start config and projects the runtime of the whole experiment matrix, for the user to approve before any Phase 5/6 run. The orchestrator imports no torch. It runs the spike's quiet-machine preflight (`--min-available-gib`, default 7.0), verifies `selection_train`, reads `verdict.chosen` from `results/spike/mps_spike.json`, checks the laya pin and the weights, refuses on low disk, and starts one fresh `ray_train.py --device mps --workers 1 --neg 8` child with the spike env. `--interrupt kill` (default) waits until `epoch-001` is registered, SIGKILLs the child's process tree `--kill-delay-s` (60) into epoch 2 and reruns the identical command, which resumes; an MPS out-of-memory exit moves to the next ladder rung in a fresh child (`compute.attempt_chain`), except one after the last epoch (`pilot.runs.resume_oom`), which ends the chain as failed; its reported reason says to rerun `compute_checkpoint.py` (the probe's storage is deleted, so a rerun starts a fresh probe), or, under `--keep-run`, the console prints the `ray_train.py` command that resumes the kept run. After the probe a BERTurk timing child (pinned weights, fp32 AdamW, batch 32, max_len 128) and a scoring probe (`score.py --n 32` of val on `--device`, temp out-root; its wall clock minus its inference seconds is the per-`score.py`-run overhead) replace the estimates. It writes `compute_checkpoint.json` + `.md` (the measured epochs, resume, projection with a basis and source per line, what-if table, disk budget, assumptions) and deletes the probe's checkpoint and Ray storage unless `--keep-run`. Every child (probe run, resume, BERTurk, scoring probe) is killed after `--probe-timeout-s` (default 3 h) and recorded as failed or timeout. A run off the protocol (not mps, not the pinned weights or committed split, another start config, `--cpus`/`--epochs`/`--seed` other than `compute.PROTOCOL` (4, 2, 0), an interrupt other than kill, BERTurk weights other than the pinned ones, a test hook) is bannered SMOKE RUN with `protocol_complete: false`; a busy-machine preflight is bannered too, and so is swap growth during a measured epoch (`compute.swap_grew_epochs`, also an assumption to confirm).
- **`results/`:** `dumps/RUN_ID/{val,test}.{npz,json}` are the committed logit dumps of majority, prior and zero-shot Laya (`laya-zeroshot-7b928d82`) on the full val and test splits, the audit record every report is recomputed from (`make baselines` rescores them; `make baseline-reports` rebuilds `reports/` from them without a model). `reports/` holds the full-test reports (`majority.json`, `prior.json`, `laya-zeroshot-7b928d82.json`) and the paired bootstrap comparisons (`compare-laya-zeroshot-7b928d82-vs-prior.json`, `-vs-self.json`); the README results table is `report.py --table results/reports`, test-enforced. `legacy/` keeps the two legacy-protocol reports (no no-intent rows, 100 test messages), labelled as not comparable by its README. `results/spike/` holds the committed spike report (`mps_spike.json` + `mps_spike.md`; verdict FITS at micro-batch 8, max_len 128, grad-accum 4, rung none); a `kaggle_plan.md` would exist there only on a DOES NOT FIT verdict. `results/compute/` holds the committed compute checkpoint (`compute_checkpoint.json` + `compute_checkpoint.md`, schema `compute_checkpoint/1`) from one real `compute_checkpoint.py` run on the M4; `tests/test_compute_report.py` keeps it consistent with `pilot/compute.py`.

## Resource notes

Each Ray worker holds about 2.6 GB. Two CPU workers ran out of memory in a 7 GB sandbox, so plan for 16 GB or more per worker. `ray_train.py` is single-node: workers read the driver-local base weights and split, so it refuses a multi-node Ray cluster. `--freeze-encoder` trains the head only. It fits small machines but gains much less. Disk: about 1.5 GB venv + 1.1 GB weights + a few MB data.
