# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Fine-tunes and evaluates the Laya `laya-multilingual` model on the Turkish banking split of Multi3NLU++ (multi-label intent detection, 48 tags), using Ray Train for distributed (DDP) training and Ray Data for distributed inference, against a fine-tuned BERTurk baseline trained with the HF Trainer (`berturk_train.py`). The pipeline ran in stages, in this order: the environment and data setup, the MPS feasibility spike, the baselines, the compute checkpoint, the Laya val selection and its final seeds, the BERTurk baseline, the confidence and latency metrics (`report.py --confidence`, `latency.py`), the frozen protocol and the final scoring (the decision rule and the few-shot protocol frozen in the hash-pinned `protocol.json`, `pilot/protocol.py`; each final seed scored once on test and HOTELS behind `score.py`'s protocol gate; the mechanical GO block, `pilot/verdict.py`, `report.py --verdict`, `results/final/`), the few-shot experiment (the frozen few-shot protocol run unchanged: label-masked bases and continued runs of both models, `--fewshot-base`, `--fewshot-draw`/`--fewshot-k` of `ray_train.py` and `berturk_train.py`, each few-shot checkpoint scored once on test behind the same gate, the committed allow-list `results/fewshot/runs.json`, the few-shot results record `results/fewshot/fewshot.json`, `pilot/fewshot_report.py`, `make fewshot-reports`, and criterion (d)'s few-shot path in the verdict, `report.py --verdict --fewshot`), and the recommendation, memo and reproduction (the recommendation rendered mechanically from the frozen verdict: INCONCLUSIVE, which counts as NO-GO; collect bank data: `report.py --recommendation`, `pilot/memo.py`, the README Recommendation section; the one-page decision memo `results/final/memo.md`, `make memo`; the one-command reproduction `make reproduce` and its eval-only form `make report`, `reproduce.py`, `pilot/reproduce.py`), and last a local demo UI over the finished results (`make demo`, `demo.py`, `pilot/demo.py`, `ui/`: a chat with both fine-tuned systems and a dashboard of the committed records, which never trains or scores). Both trainers can also write live TensorBoard scalars on request (`--tensorboard DIR` of `ray_train.py` and `berturk_train.py`, `pilot/tensorboard.py`), outside every run id and record. Dependencies are pinned in `pyproject.toml` and hash-locked in `requirements.txt` (Python 3.12, binary wheels only); `make env` installs them into `.venv`. There is no linter. The scripts are run directly.

## Conventions

- snake_case modules and functions, UPPER_CASE module constants, terse locals (`a` parsed args, `c` train config, `tok`,
  `mb`). The only production class is `Predictor` in `score.py` (a Ray Data actor).
- Every function and method carries parameter and return type hints: Python 3.12 builtin generics (`list[str]`,
  `dict[str, Any]`, `tuple[int, ...]`), `X | None`, and `typing.Any` where the precise type would need an import the
  module must not make (torch-free and numpy-free modules are guarded by tests: never add a heavy runtime import for an
  annotation). Annotations must be true.
- `%`-formatting for messages, ~120-column lines, hand-formatted. Refusals are `raise SystemExit("<what>; <fix>")`,
  raised before any model load or `ray.init` where possible; argument errors use `ap.error(...)`.
- Every script and `pilot/` module opens with a docstring (purpose, design notes, `usage:`); helpers that encode a
  contract carry a docstring stating it and the return value. Files open with `encoding="utf-8"`, JSON is written with
  `ensure_ascii=False` and atomically (`pilot.data.write_atomic`). Records carry repo-relative paths and sha256s, never
  local paths.
- Frozen records stay byte for byte: never edit `protocol.json`, any `.json`, `.npz` or `.svg` under `results/`, or
  anything under `data/`. A code string constant that a committed record holds (the protocol, verdict, metric, latency
  and few-shot rule texts, record keys, schema names) must stay byte-identical; markdown under `results/` and the
  README's generated blocks are regenerated from the records, never hand-edited.

## Architecture

- **Task framing:** each of the 48 intent tags in `intents.py` (`INTENTS`) becomes one Laya `noul` (yes/no) question, so one forward pass gives a probability per tag. `QUESTIONS` is defined only in `intents.py` and imported by `pilot/data.py` and `score.py` (a test fails on a second definition). If you change tag wording, regenerate the data and re-run the baselines, because the question text is the model input; `data/splits.json` records `questions_sha256`, so a wording change without a refreeze fails `make test`.
- **Splits:** `make data` writes five outputs to `data/splits/`: `selection_train` (folds 0–13, 1,450 msgs), `val` (14–15, 208), `final_train` (0–15, 1,658), `test` (16–19, 413) and `hotels_probe` (HOTELS 0–19, 1,009, out-of-domain; only the 22 `ood_scoring_tags` are valid gold). Every row labels all 48 tags; no-intent messages are kept by default (`--no-include-no-intent` to another `--out`; consumers read that variant with `--manifest OTHER_DIR/splits.json`, which may not change any split's role, path or folds versus `pilot.data.SPLITS`; outputs record `manifest_is_committed`). The committed `data/splits.json` registers each file's path, role and sha256. `pilot.data.verify_split_file` is the only verifier and hard-fails on a tampered, unregistered or wrong-role file; there is no override (regenerate with `make data`, or deliberately refreeze with `prepare_data.py --rewrite-manifest`, which invalidates downstream results). Duplicate uids hard-fail at prepare time.
- **JSONL schema:** `{"state": text, "uid", "questions": {tag: {"type": "noul", "instructions": ...}}, "expected": {tag: bool}}`. This is Laya's training format. Gold labels come from `expected` (`pilot.dumps.read_gold`); dumps never hold `state`.
- **`pilot/` (shared, mostly torch-free):**
  - `pins.py`: every pinned revision and sha256 (dataset, 40 raw folds, Laya, BERTurk, OOD tag subset).
  - `data.py`: the split producer and `verify_split_file`; `refuse_held_out` (no committed test content in any train split and no committed val content in `selection_train`, keyed on sha256, uids_sha256 or (uid, message) pairs, so a manifest copy cannot relabel held-out content); `holds_committed`; `require_committed_files` (the content checks fail closed while a committed split file they read is missing).
  - `audit.py`: the report-only duplicate audit to `data/audit/`, hash-registered in the manifest, never changes splits.
  - `weights.py`: `fetch(pin)` downloads only the pinned safetensors files at the full commit SHA and checks their sha256 (`make weights`). `identity(dir)` of a local checkpoint hashes the weights, `rl_agent_config.json` and every file under `tokenizer/` and `encoder/` (`files_sha256`), with `tokenizer/tokenizer_config.json`, which `laya.load` rewrites on the first load, bound by its normalized JSON (`NORMALIZED_KEY`, a mirror of laya's rewrite that `tests/test_laya_adapter.py` checks against laya). `checkpoint_digests` + `verify_files` check every one before a load; `checkpoint_digests` refuses a local checkpoint without `tokenizer/tokenizer_config.json` or `encoder/config.json` (`dumps.LOCAL_REQUIRED_FILES`), which laya would otherwise read unpinned from the Hub. `check_tokenizer_config_rewritable` refuses, on the driver before any load or `ray.init`, a `tokenizer_config.json` laya would have to rewrite in a read-only `tokenizer/` or that is not a JSON object; `check_tokenizer_config_rewritten` is the post-load backstop (it only warns).
  - `dumps.py`: the logit dump format: `write_dump` and `load_dump`, the only reader, which hard-fails on any npz, hash, split, question or tag-order mismatch (an unreadable npz is refused in one line, never a traceback); `read_gold`; `run_id`; `READ_ROLES` = `EVAL_ROLES` (val, test) + `ood_probe`; `gold_valid_tags(entry, manifest)`: all 48 tags for a banking split, the manifest's 22 `ood_scoring_tags` for hotels_probe, in `INTENTS` order; `training_digest`.
  - `metrics.py` (numpy only, names no system): micro/macro-F1, exact match, top-1, per-tag F1 with support, the val θ rule `select_theta`, `seed_average`, `paired_bootstrap`; on gold Y and probabilities P [n, 48] (never logits): calibration (`ece_bins`, `brier`, `nll` with P clipped to `NLL_EPS` 1e-12, `classwise_ece` over `ECE_BINS` 15 equal-width bins averaged over all 48 tags, `reliability`, `calibration`, `CALIBRATION_RULES`); abstention (`message_confidence(P, θ)`, the one rule: the joint decision probability, the sum of log q with q = p if p >= θ else 1 - p, `CONFIDENCE_RULE`; `selective` at `COVERAGES` 50/70/80/90 with the integer cut (c * n + 99) // 100 and stable ties, `n_tied_at_cut`, AURC; `COVERAGE_RULE`, `AURC_RULE`); false positives (`wilson(k, n)`, the 95% Wilson interval, and `fp_rate(Y, P, θ, cols=None)`: the no-intent rate over all 48 columns and the out-of-domain rate over the 22 banking-only columns, `FP_RULE`); `paired_bootstrap_extra` (Brier, classwise ECE and precision at a coverage on the same `bootstrap_weights` draw, `BOOT_EXTRA_RULE`); `average_precision` and `new_tag_ap` (sklearn semantics, a tag with no positive refused, `AP_RULE`; the few-shot primary metric); the θ grids `GRID`/`GRID_CENTI`.
  - `laya_adapter.py`: the only module that touches Laya's private API, pinned to laya 0.4.6; `tests/test_laya_adapter.py` checks the version and every wrapped signature, runs a tiny-model round trip, and an AST guard fails on a private laya import anywhere else. `items_per_question` (the few-shot masking proof's count of laya items per question) is the only reader of laya's item layout outside laya. When the lock moves `laya`, fix the adapter, not the callers.
  - `spike.py` (never imports torch): the MPS spike's grid and protocol constants, worker env, neg8 sampling, padding, timing summary, swap readers, verdict and report builders.
  - `runs.py`: the run-record schema of `ray_train.py` (`EPOCH_FIELDS`, `SEGMENT_FIELDS`, `read_record`); the run identity (`IDENTITY`, `NOT_IDENTITY`, `DROPPED_WHEN_NONE`, `canonical`, `run_id`, `check_state`); `neg_items`; the MPS fallback ladder (`SPIKE_START`, `RUNG_NEXT`, `rung_label`, `rung_flags`, `oom_message`, `failure_line`, `STAGE_FINAL_SAVE`, `STAGE_FINALIZE_MOVE`, `RESUME_STAGES`); `disk_need_bytes`.
  - `tensorboard.py` (the stdlib and `pilot.data` only at import; a subprocess test guards it): the TensorBoard helpers of both trainers. `check_logdir(path, outputs)` returns the realpath of a `--tensorboard` DIR and creates nothing. It judges the DIR by its realpath string and by file identity (`os.path.samestat` of every existing ancestor, so no symlink, case variant or bind mount steers it), and refuses, in this order: a DIR under `FORBIDDEN` (results/, data/, ui/, protocol.json); one under the run's own outputs (`--storage`, `--out`); one that is a file or lies inside one; and one inside the repo that `git check-ignore` does not report ignored (an event file's name carries the host name; `tensorboard/` is gitignored; without git it is accepted). The trainers call it on DIR and again on DIR/RUN_ID, before `--print-run-id`. `STEP_TAGS`, `EPOCH_TAGS`, `RATE_TAGS` and `TAGS` are the fixed tags: `write` refuses any other tag, skips None values and never flushes. `segment_suffix` (`.segment-NNN`, Laya) and `pid_suffix` (`.pidN`, BERTurk) give every writer its own file, because tensorboardX opens an event file 'wb' under a name built from a 10-digit second and the host name. `open_writer(logdir, purge_step, suffix)` imports tensorboardX lazily (it imports torch) and opens a writer with the purge step, `FLUSH_SECS`, `MAX_QUEUE` and comet disabled; an `OSError` becomes a one-line refusal. `memory_scalars`, `step_scalars` and `epoch_scalars` build the scalars (`GIB`, `MIB`).

- **`berturk_train.py`:** the BERTurk trainer: `dbmdz/bert-base-turkish-cased` at its pinned revision, fine-tuned with the HF Trainer as a 48-label multi-label `BertForSequenceClassification` (labels in `INTENTS` order), one process, no Ray, `--device cpu|mps|cuda`; `--data` is refused when it holds committed held-out content. The loss is a masked BCE passed as `compute_loss_func` (a masked label is `MASK_LABEL` -100 and gets zero gradient). The optimizer is four AdamW param groups (`pilot.berturk.optimizer_groups`): the encoder at `--lr` (default 2e-05) and the fresh classifier head at `--head-lr` (default 1e-4, Laya's head LR), handed over as `Trainer(optimizers=(optimizer, None))` so the Trainer still builds the linear schedule and its 10% warm-up over both LRs. `--epochs` defaults to 30; batch 32, max_len 128, fp32, no gradient checkpointing, `transformers.set_seed` right before the head is created. Every epoch writes an export `<storage>/<run_id>/exports/epoch-NNN` with exactly the five `CHECKPOINT_FILES` (tokenizer files copied byte for byte), whose `berturk_train.json` (`berturk-train/1`) holds the run id, canonical config, epoch, schedule, calibrated false, T 1.0 and the run record. The run id is `pilot.berturk.run_id` of the canonical config; there is no resume: an existing run dir is refused, a run is rerun from scratch (`--print-run-id` prints the id). Final seeds: `--stop-after-epoch K`; `--postfit RECORD --reference REF --out DIR` refuses, before any fetch or run dir, unless REF is the record's reference check reading ok or resolved (`check_reference_for_final`) and every setting is the chosen run's (`check_final`), and stamps the record's T (calibrated true, `postfit = final_block`). Storage defaults to `berturk_runs/` (gitignored); it refuses below `pilot.berturk.disk_need_bytes` free. Few-shot: the same two modes as `ray_train.py`, bound the same way before any fetch, load or run dir (the frozen `rules.base_runs.berturk` must name `MASK_LABEL` and float32). `--fewshot-base` keeps every message and masks the held-out columns in every label vector (the run refuses to train when any label of those columns is not masked). `--fewshot-draw D --fewshot-k K --base <masked base>` continues from the base's own fine-tuned head on the frozen support plus replay rows in `selection_train` file order (`berturk_rows`: a support row keeps all 48 labels, a replay row masks the held-out tags; no `--stop-after-epoch`); `from_pretrained` must report no missing, unexpected or mismatched key, and `optimizer_groups(..., continued=True)` requires that nothing was newly initialised (no fresh head, no weight imprinting). Both modes refuse `--postfit`, `--reference` and `--max-messages`; the run record's `fewshot` entry is the masking proof (counts, tags and digests, never a uid). TensorBoard: `--tensorboard DIR` (`NOT_IDENTITY` in `pilot.berturk`, never recorded; the same `check_logdir` calls, before the few-shot protocol, the split read and any fetch, load or run dir, and on DIR/RUN_ID before `--print-run-id`) adds a second `TrainerCallback` after the first. The batch loss is noted in `compute_loss_func`, the LRs in `on_optimizer_step` (before the scheduler steps) and the pre-clip norm by a flag-on-only wrap of `trainer.accelerator.clip_grad_norm_` that returns accelerate's value unchanged; a step without the noted norm or LRs is refused, naming the transformers version. It writes per step at the Trainer's global step and per epoch at the step that closes it (`epoch/save_s` None), into one `.pidN` file per process opened with purge step 1 (an existing DIR/RUN_ID is not refused: a from-scratch rerun hides the old file's steps) and closed in a `finally` block; the `TrainingArguments` are unchanged.
- **`score.py`:** the only place a model runs. It turns one system on one split into `results/dumps/RUN_ID/SPLIT.npz` (float32 logits [n, 48] in `INTENTS` order + uids, no text) and a JSON sidecar (split and manifest hashes, system identity, temperature, run id). The input must be a registered split with a matching sha256 and a role in `main`'s `roles` (default `SCORE_ROLES`: test, val and ood_probe; train splits are refused before any model load or `ray.init`). `hotels_probe` is open to `--model laya` and `berturk` only (majority and prior are refused there naming the role: `TRAINED_ON` has no HOTELS source), and `evaluate.py` passes `roles=("test", "val")`. `--model laya` (default; `--checkpoint multilingual` = the pinned, digest-verified weights, run id `laya-zeroshot-7b928d82`, or a local checkpoint dir, run id `laya-<model_sha256[:12]>-<config_sha256[:8]>-<files digest[:8]>` over every file `laya.load` reads, `pilot.weights.identity`) loads through the public `laya.load(..., expected_sha256=...)` and reads the raw noul margins and served temperature through `pilot/laya_adapter.py`. Scoring is fp32 on every device: laya 0.4.6 autocasts to fp16 on mps and cuda, so `la.force_fp32` turns autocast off after the load, the sidecar records laya's load-time default (`laya_default_amp`, `laya_default_dtype`), and `check_agent` refuses another device, a non-fp32 dtype, autocast on or a GPU-to-CPU fallback, after every batch too. `--device cpu|mps|cuda` (default cuda when `--gpus-per-worker > 0`, else cpu); mps scores in-process only (`--workers 0`). `--workers N` uses N Ray Data `Predictor` actors (one checkpoint load each, `--cpus-per-worker` CPUs and torch threads, rows reassembled by uid into split-file order; an actor killed mid-split is restarted and its batch retried; a refusal inside an actor is re-raised as a plain `RuntimeError` marked `score.REFUSAL`, which Ray never retries, and the driver ends the run with the refusal's own line and no dump). `--model majority|prior` are baselines from the matching training split, never the scored labels (`final_train` for test, `selection_train` for val), stored as clipped logits with T = 1. `--n N` scores a seed-0 shuffled subset for debugging only, never under `results/dumps`. An existing `<run_id>/<split>` dump is refused before any load unless `--force` (`make baselines` passes it). A fine-tuned checkpoint's sidecar records its `seed` and a `training` block (train run id, split, encoder LR, epoch and schedule, rung, calibrated, the postfit sha256, the canonical run config and `config_sha256_sans_seed`, `pilot.dumps.training_digest`).
  - **The protocol gate:** `gate_trigger` keys on content over every parsed row before `--n`: every local Laya checkpoint (any `--checkpoint` but the pinned `multilingual`, keyed on the identity, never on the checkpoint's own claims) on a split with role test or ood_probe (`GATED_ROLES`) under the committed manifest, any BERTurk checkpoint on such a split under any manifest, and either on a split of any role and manifest whose sha256 or uids_sha256 is the committed test or hotels_probe entry's, or that holds any (uid, message) pair of the committed `test.jsonl` or `hotels_probe.jsonl` (`pilot.data.holds_committed`; a uid alone is not the key, so the synthetic CPU smoke test stays outside it). The content check fails closed (`require_committed_files`). A triggered run is refused before any checkpoint hashing, fetch, model load or Ray start (`protocol_gate`) unless `require_frozen` passes, there is no `--n`, no `--force` and no `--out-root` other than results/dumps, the manifest is the committed one and `gated_split` names the split, and `--device`/`--workers` are the protocol's scoring block (mps, 0). After the identity is hashed and before any file is parsed or a model loads, the dump run id must be admitted (`require_admitted`): one of that system's final seeds (`final_seed_allowed`), on test or HOTELS, or a few-shot checkpoint of that system listed in the committed allow-list `results/fewshot/runs.json` (`pilot.fewshot.admitted`, which runs `check_runs` at every call), on test only (HOTELS is never opened for it), and only when the checkpoint re-derives its listed entry (`rederive_entry`: the `entry_of` of the script `fewshot.py`, from the record bytes the identity hashed, equal but for `checkpoint_name`). Once means once: an existing gated dump is refused, and so is an npz an interrupted gated run left without its sidecar (delete it and rerun the one command). An admitted dump's sidecar carries `protocol_sha256`, and an admitted few-shot dump's also `fewshot_runs_sha256`; every other dump (a masked base's ungated val dump included) has no such key. Every gate refusal is one line starting with `GATE` (`"protocol gate: "`) naming the checkpoint, the split, the trigger and the fix.
  - **BERTurk:** `--model berturk --checkpoint DIR` scores a `berturk_train.py` export or final seed in-process only (`--workers 0`), fp32 on cpu, mps or cuda (`check_bert` refuses float16, another device or autocast, after the load and every batch); it refuses a checkpoint missing a `CHECKPOINT_FILES` entry, a config.json that does not score `INTENTS` in order and a lowercasing tokenizer; the dump run id is `pilot.berturk.dump_run_id`, the logits are the classifier logits, the shipped T is `berturk_train.json`'s. `score.load_bert(checkpoint, ident, device, threads)` is the one BERTurk loader, shared with `latency.py`, so the timed checkpoint is loaded exactly as it is scored.
- **`report.py`:** numpy only (no torch, Ray, laya or model). `report.py RUN_DIR [--split test]` recomputes every metric from verified dumps: two temperature variants (`shipped`, the headline, and `raw`, T = 1), each with a row at θ 0.5 and at the val-selected θ (global θ on val micro-F1 over 0.05..0.95 in 0.01 steps; per-tag θ only for tags with 10 or more val positives; ties toward 0.5; chosen on the run dir's full val dump, never on test). Rows carry micro/macro-F1, exact match, top-1 (over messages with a gold tag) and per-tag F1 with support. `--compare A_DIRS B_DIRS` is the paired message-level bootstrap (B = 10,000, seed 0; per-seed probabilities averaged before thresholding; descriptive only); a side of several run dirs must be distinct recorded seeds of one system. `--table PATH...` renders the baselines results table. Reports hold no timestamps, so they rebuild byte for byte.
  - **θ-source rules (each keyed on content under any manifest and failing closed while a committed split file is missing):** θ is applied only to a dump from the same source as its val dump (`SAME_SOURCE_KEYS`: system kind, checkpoint identity, shipped T, scorer device, dtype and amp; the path only when the identity binds every file `laya.load` reads, `binds_every_file`). A val dump of a model trained on another split than `selection_train` or bound to a postfit record (a final seed: its val is in-sample) is refused as a θ source (`refuse_in_sample_theta`). A final seed is never reported on val or on a split holding committed val or final_train content (`refuse_final_seed_training_content`), in a report, in `--compare` and in `--confidence`. A θ-source val split holding committed test, HOTELS or selection_train content (`THETA_HELD_OUT`) is refused (`refuse_held_out_theta`).
  - **Confidence:** `report.py --confidence RUN_DIR --split val|test|hotels_probe [--postfit RECORD] [--out X.json]` writes a `confidence/1` record whose T and θ come from one of three bindings (`confidence_binding`): `postfit_candidate` (a selection candidate's dump, bound by `dump_sha256` to the record's candidate, its val-fitted T and θ), `final_seed` (the record named by `training.postfit_sha256`; on test or hotels_probe only; the record is refused unless its T and θ were fitted on banking val content, `refuse_held_out_record`) or `val_selected` (run_report's val rule, e.g. zero-shot Laya). A val record carries `in_sample` true and `IN_SAMPLE_CAVEAT`, per variant a calibration block, `selective` at θ 0.5 and at θ and `no_intent_fp` (k/n, rate, Wilson); `--out` also writes `X.svg` (`render_svg`, plain SVG). `--split hotels_probe` gives an OOD record (`ood_fp` on `gold_valid_tags`; no SVG). `--confidence-table PATH...` prints `render_confidence` (`CONFIDENCE_SECTIONS`, `CONFIDENCE_DISCLOSURE`, `TEST_NO_INTENT` 15; `svg_dir` derived from the inputs' common directory, `confidence_svg_dir`). `run_report` and `compare` refuse role `ood_probe` (`refuse_ood_role`).
  - **Final seeds and the verdict:** `report.py RUN_DIR --split test --postfit RECORD` reports a final seed at its record's θ through `final_seed_binding` (record sha256, system kind, `refuse_held_out_record`, T within `T_MATCH`); without `--postfit` a final seed's val-selected rows are null with `FINAL_SEED_REASON`. `--verdict [--out results/final/verdict.json]` writes `verdict_report()` = `verdict_from(*pilot.protocol.require_frozen())`: the protocol's definitions and bootstrap code texts equal to the live ones (`frozen_code`; a code change under unchanged texts is caught only by the `data`-marked byte rebuild), every protocol input's sha256 checked, exactly the protocol's final-seed test dumps loaded, each model seed-averaged at its record T with the record's theta.shipped, `system_deltas`, the prior floors recomputed, the per-seed rows, then `build_verdict`. `--verdict --fewshot RECORD` passes the few-shot results record; `fewshot_input` refuses it unless its protocol sha256 is the pin, its primary k is criterion (d)'s few-shot k, the runs manifest it names is its own with the same decision, and its primary block equals `pilot.fewshot_report.primary` recomputed from that manifest and the committed dumps (no tolerance). `--final-table` and `--go-block`, `--recommendation` and `--memo` (each `VERDICT_JSON [--out PATH]`) print their renders only after `require_frozen` passes and `pilot.verdict.check_record` binds the record; `memo_inputs(v)` reads the few-shot record at the verdict's `fewshot.record` path (refused unless its sha256 is the one the verdict binds), the final confidence records and the latency reports.
- **`evaluate.py`:** a thin wrapper kept for the old CLI: it runs `score.py --model laya` (with `roles=("test", "val")`) and prints `report.run_report` of the dump (no metric or model code of its own; a test enforces that). Without `--out-root` the dump goes to a fresh temp dir, never `results/dumps`.
- **`latency.py`:** the latency harness, reported, not gated (latency is not a decision criterion; a budget is left to a later version). One run times every final seed of one system (`--system laya|berturk`) listed in its final manifest (`--final-manifest`; seeds under `--checkpoint-root`, default the repo root) on one device, in this process, no Ray, at batch 1, through the path that scored the dumps: Laya via `score.resolve_checkpoint`, `la.check_version` and `score.Predictor` (fp32, autocast off), BERTurk via `score.check_berturk` and `score.load_bert`. After each seed's load, one untimed pass runs every val message it then times (`WARMUP_POLICY` `full_pass_per_seed`; there is no warm-up flag), then every val message is timed between device syncs (`--threads` 4). The seeds run in manifest order, so a residual seed-order effect is not separated from a seed effect; the committed Laya reports show seed 0 slower (about 0.9% on CPU, 0.1% on MPS), disclosed in the README. Refusals before the preflight, torch or any load: a split not registered with role val, a split holding committed test or HOTELS content, a final manifest not of the system, a missing seed dir or one whose identity or dump run id is not the manifest's; after the load, a served T other than the manifest's. The quiet-machine preflight is `compute_checkpoint.preflight` (`--min-available-gib` 7.0; 0 records a busy-machine run). The `latency/1` report holds no text, uid list or local path. `--render DIR [--out]` prints the markdown without torch. Run one MPS job at a time.
- **`fewshot.py`:** the few-shot runner; every mode calls `require_frozen` first (training runs through `ray_train.py` and `berturk_train.py`, scoring through `score.py`): `--support-sets [--manifest M]` (the manifest's selection_train bytes verified and bound to the block's source hashes, `check_draws`, a JSON summary with no uid list or text); `--counts`; `--projection --out PATH` (the compute decision record `fewshot-projection/1`, written once; `--ladder-failure TEXT` rewrites a primary record into the fallback one); `--inspect CKPT...` (one runs-manifest entry per checkpoint, `entry_of`); `--runs-manifest CKPT... --out PATH` (the allow-list `fewshot-runs/1`, written once, every slot filled, each continued entry bound to its base); `--prune CKPT...` (deletes a listed checkpoint only once its verified dumps exist; a symlink, an unlisted dir or a final seed is refused); `--drop-storage CKPT --storage DIR`; `--report --out PATH` (`make fewshot-reports`); `--render PATH` (the README few-shot block).
- **`reproduce.py`:** the CLI over `pilot/reproduce.py`: `--mode full` (the default, `make reproduce`) or `--mode eval-only` (`make report`), `--verify-checkpoints` and `--checkpoint-root DIR`, `--dry-run [--all]`. It prints the interpreter and the plan first. `make reproduce` runs `reproduce.py --mode $(MODE)` (`MODE` defaults to full), `make report` is `make reproduce MODE=eval-only`, `VERIFY_CHECKPOINTS=1` adds `--verify-checkpoints`, and `make memo` runs `report.py --memo` into `results/final/memo.md`.

It refuses a missing `ui/dist/index.html` before the server starts. - **`mps_spike.py`:** the MPS feasibility spike: does a full-encoder Laya fine-tune fit on the 16 GB M4? The orchestrator imports no torch. ## Resource notes

Each Ray worker holds about 2.6 GB. Two CPU workers ran out of memory in a 7 GB sandbox, so plan for 16 GB or more per worker. `ray_train.py` is single-node: workers read the driver-local base weights and split, so it refuses a multi-node Ray cluster. `--freeze-encoder` trains the head only. It fits small machines but gains much less. Disk: about 1.5 GB venv + 1.1 GB weights + a few MB data. BERTurk on MPS peaks at about 6.6 GiB (the 30-epoch selection run; the final seeds at up to 6.3 GiB); run one MPS job at a time. A 30-epoch selection run takes about 10 minutes and its 30 exports need about 12.4 GiB of transient disk (`berturk_train.py` refuses below about 13.4 GiB free); `postfit.py --prune` frees each export once its val dump exists. The latency runs (all four, the six final seeds) take about 23 minutes on the M4, one job at a time on a quiet machine (Laya on CPU alone about 15 minutes).
