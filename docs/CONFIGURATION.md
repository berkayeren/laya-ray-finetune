# Configuration

The pilot is configured by command-line flags, `make` variables and a few committed files. The code reads no
environment variable for its own settings, and there are no `.env` files and no config file you are expected to
edit. Each script's `--help` lists its flags. This page covers the settings that change behaviour, their defaults,
and the committed files that pin everything else.

The [README](../README.md) is the full command reference, and the [guide](GUIDE.md) explains the pipeline.

## Environment variables

The code reads no environment variable to configure itself. `pilot/data.py` states that the manifest check has
"no override flag or environment variable", and the test hooks are hidden flags ("never an env var", `ray_train.py`).
You can set the one variable below in your shell. The variables after it are set by the code itself.

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| `HF_HUB_OFFLINE` | Optional | unset | Set `HF_HUB_OFFLINE=1` to reuse the hub cache after the first fetch of the pinned weights (`pilot/weights.py`). The weights are still sha256-checked against `pilot/pins.py`. |

**Set by the code on MPS (do not set them yourself).** `pilot.spike.spike_env` builds the environment of every MPS
training process. `ray_train.py` passes it to the worker through `ray.init(runtime_env)` and checks it in the
worker (`check_env`), which refuses a mismatch. `berturk_train.py` writes it into `os.environ` before torch is
imported. `tune.py`, `mps_spike.py` and `compute_checkpoint.py` pass it to their trials and child processes.

| Variable | Value set | Purpose |
|----------|-----------|---------|
| `PYTORCH_ENABLE_MPS_FALLBACK` | `0` (strict; the spike reruns with `1` only when an op is not implemented) | No silent CPU fallback for MPS ops |
| `PYTORCH_MPS_HIGH_WATERMARK_RATIO` | `1.0` | MPS allocator high watermark, as the spike measured it |
| `PYTORCH_MPS_LOW_WATERMARK_RATIO` | `1.0` | Must be set with HIGH; HIGH=1.0 alone crashes the first MPS call |
| `OMP_NUM_THREADS` | the run's CPU count (`--cpus-per-worker` / `--cpus`) | Thread count |
| `TOKENIZERS_PARALLELISM` | `false` | No tokenizer thread pool inside workers |
| `HF_HUB_OFFLINE` | `1` | Workers read only the weights the driver already fetched and verified |

`latency.py` records the value of `PYTORCH_ENABLE_MPS_FALLBACK` it saw in its report (`mps_fallback_env`).

## Config file format

These files configure the pilot. They are committed and pinned. Edit them only where the table allows it.

| File | Format | What it holds | Edit? |
|------|--------|---------------|-------|
| `pyproject.toml` | TOML | Exact direct pins (`requires-python = "==3.12.*"`, `laya==0.4.6`, `torch==2.14.1`, `ray[train,data]==2.59.0`, ...), the `dev` extra, and the pytest config (`testpaths`, `pythonpath`, strict markers `unit`, `data`, `weights`, `ray`, `mps`). The project is never pip-installed (no `[build-system]`). | Maintainers only. Run `make lock` afterwards and commit both files together. |
| `requirements.txt` | pip hash lock | Universal, hashed lock generated by `make lock` (`uv pip compile ... --exclude-newer $(LOCK_DATE)`). `make env` installs it with `--require-hashes --only-binary :all:`. | Never by hand. Regenerate it with `make lock`, then prove it with `make lock-check`. |
| `pilot/pins.py` | Python constants | Every pinned revision and sha256: the dataset (`DATASET_REPO`, `DATASET_REVISION`, the 40 raw fold hashes), `LAYA`, `BERTURK`, `OOD_SCORING_TAGS`. | No. A changed pin invalidates the downstream results. |
| `pilot/defaults.py` | Python constants | The default recipe for **new** training runs (`LAYA`, `BERTURK`), plus its source (`SOURCES`: record path, sha256, best trial, epoch). See [Defaults](#defaults). | No. `tests/test_defaults.py` binds every value to `results/tune/*.json` by JSON text. |
| `data/splits.json` | JSON | The split manifest. Top-level keys: `audit`, `dataset`, `intents_order`, `ood_scoring_tags`, `options`, `questions_sha256`, `schema_version`, `seeds`, `splits`, `uid_check`. `splits` registers `selection_train`, `val`, `final_train`, `test` and `hotels_probe`, each with path, role, folds and sha256. | No. It is written by `make data`. Refreeze it only on purpose with `prepare_data.py --rewrite-manifest`, which invalidates downstream results. |
| `protocol.json` | JSON (`protocol/1`) | The frozen decision protocol. Top-level keys: `schema`, `title`, `units`, `frozen`, `inputs`, `splits`, `systems`, `references`, `scoring`, `variant`, `seed_averaging`, `bootstrap`, `criteria`, `collapse`, `verdict`, `definitions`, `fewshot`, `known_at_freeze`, `power_context`, `assumptions`, `delegation`, `code`. Its exact bytes are pinned by `pilot.protocol.PROTOCOL_SHA256`. | Never. `require_frozen` refuses a missing, changed or re-serialised file. Check it with `python -m pilot.protocol --check`. |
| `intents.py` | Python constants | The 48 tags (`INTENTS`) and their question text (`QUESTIONS`), which is the model input. | Only together with `make data` and a rescore. `data/splits.json` records `questions_sha256`, so a change in wording without a refreeze fails `make test`. |
| `ui/package.json`, `ui/package-lock.json`, `ui/.npmrc` | npm | The demo UI's exact pins (`"engines": {"node": ">=22.12.0"}`) and the committed lockfile. `.npmrc` sets `save-exact=true`, `engine-strict=true`, `ignore-scripts=true`. | Maintainers only. |
| `Makefile` | GNU Make | The front-door targets and the [make variables](#make-variables) below. | Override variables on the command line. Do not edit them. |

| Variable | Default | Used by |

## Required vs optional settings

Wrong settings are refused before any model load or `ray.init` where possible. The refusal is
`SystemExit("<what>; <fix>")`, or exit code 2 from argparse (`ap.error`).

**Required arguments**

| Script | Required | Validation |
|--------|----------|------------|
| `ray_train.py` | `--data`, `--out` | `--data` must be a split registered with role `train` that holds no committed held-out content (`pilot.data.verify_split_file`, `refuse_held_out`). `--epochs` must be at least 1. `--neg` must be 0 or positive. `--stop-after-epoch` must be in `1..--epochs - 1`. `--device mps` needs `--workers 1` ("use --workers 1"). `--amp` is refused on mps and cpu ("--amp is CUDA-only"). `--freeze-encoder` cannot be combined with `--freeze-embeddings`. `--fewshot-draw` and `--fewshot-k` must be given together. A few-shot mode refuses `--postfit` and `--max-messages`. A multi-node Ray cluster is refused. |
| `berturk_train.py` | `--data` | The `--data` rules above. `--epochs` and `--batch` must be at least 1, `--lr` and `--head-lr` positive, `--warmup-ratio` in `[0, 1)` and `--weight-decay` at least 0 (`check_recipe`). `--postfit` needs `--reference` and `--out`. An existing run dir is refused (there is no resume). The run is refused when free disk is below `pilot.berturk.disk_need_bytes`. |
| `score.py` | `split_jsonl` (positional) | The split must be registered with role `val`, `test` or `ood_probe`, and its sha256 must match. `--model berturk` needs `--checkpoint DIR`. `--checkpoint` applies only to `laya` and `berturk`. `--n` must be positive. On MPS it scores only with `--workers 0`. An existing dump is refused unless you pass `--force`. A fine-tuned checkpoint on test or HOTELS passes only through the protocol gate. |
| `report.py` | `RUN_DIR` or one mode flag | `--split` is one of `val`, `test`, `hotels_probe`. |
| `postfit.py` | run dirs or one mode flag | Each mode refuses the flags of every other mode. Test input is refused. |
| `latency.py` | `--system` (or `--render DIR`) | `--split` must be registered with role `val`. |
| `tune.py` | `--system` (or `--status`, `--check`, `--render`) | A write under `results/` is allowed only for the committed search (`--trials 20`, `--seed 0`, `--device mps`, the pinned base, the committed manifest). |
| `fewshot.py` | exactly one mode flag | Every mode calls `pilot.protocol.require_frozen` first. |
| `demo.py` | none | Refuses to start when `ui/dist/index.html` is missing (run `make demo`, which builds it). |

**Required files**

| File | Needed by | Without it |
|------|-----------|------------|
| `data/splits/*.jsonl` (created by `make data`) | every trainer, scorer and report that reads a split | Refused, naming the path. Regenerate with `make data`. |
| `data/splits.json` (committed) | every split consumer | Refused. There is no override. |
| `protocol.json` with the pinned sha256 | `score.py` (gate), `report.py --verdict` and its renders, `fewshot.py`, the few-shot trainer modes, `demo.py` | Refused by `require_frozen`. Restore it with `git checkout -- protocol.json`. |

## Defaults

### Tuned defaults of new training runs

A plain training command gets the best configuration of the committed exploratory search
(`pilot/defaults.py`). Every committed run used the **frozen recipe** instead, and its command passes the
recipe flags explicitly, so its run id is unchanged.

| Setting | `ray_train.py` (Laya) default | Frozen Laya recipe | `berturk_train.py` default (plain command) | Frozen BERTurk recipe |
|---------|-------------------------------|--------------------|--------------------------------------------|-----------------------|
| Encoder LR | `--encoder-lr 2.9660069889947058e-05` | `2e-05` | `--lr 6.637303455962178e-05` | `2e-05` |
| Head LR | `--head-lr 9.811131074677546e-05` | `0.0001` | `--head-lr 0.00020030926548084864` | `0.0001` |
| Epochs | `--epochs 6` | `4` (10 for a continued few-shot run) | `--epochs 20` | `30` |
| Negatives per message | `--neg 16` | `8` | n/a (full label rows) | n/a |
| Batch | n/a | n/a | `--batch 16` | `32` |
| Warm-up ratio | n/a | n/a | `--warmup-ratio 0.06` | `0.1` |
| Weight decay | n/a | n/a | `--weight-decay 0.0` | `0.01` |

How the defaults resolve differs between the two trainers:

- **`ray_train.py`** uses the tuned values as plain argparse defaults. A final-seed or few-shot command that omits
  a recipe flag is not trained under the tuned recipe. It is refused by the existing bindings
  (`pilot.postfit.check_final`, `pilot.fewshot.check_base`, `check_continued`), which name the first key that
  differs.
- **`berturk_train.py`** defaults its six recipe flags (`--epochs`, `--lr`, `--head-lr`, `--batch`, `--warmup-ratio`,
  `--weight-decay`) to `None`. Each omitted flag is resolved from the run's context (`recipe_context`, `resolve_recipe`).
  In order: a `--postfit` record gives its chosen selection run's config, `--fewshot-base` gives the frozen
  selection run's config, `--fewshot-draw`/`--fewshot-k` give the masked base's config, and only a plain command
  gets `pilot.defaults.BERTURK`. A flag you give always wins and is still checked by the bindings.
- **Resuming a Laya run started under the former defaults.** The run id hashes the resolved recipe. A plain Laya
  run started before the tuned defaults existed resumes only when you spell out its old recipe:
  `--epochs 4 --encoder-lr 2.5e-05 --head-lr 0.0001 --neg 8`. Without those flags the command names another run id
  and starts a fresh run in its own `<storage>/<run_id>/`.

The search's fixed settings and its device are **not** defaults. A Laya trial ran at `--max-len 128 --micro-batch 8
--grad-accum 4` on one MPS worker. A plain `ray_train.py` command keeps `--max-len` unset (the base config's
value, 512), `--workers 2` and `--device cpu`. To run the trial's recipe, pass
`--device mps --workers 1 --max-len 128` yourself, as in the README Run block.

## Per-environment overrides

There are no `.env.development` / `.env.production` files and no `NODE_ENV`-style switch. Machine differences are
handled by flags:

- **Device.**
  - Apple GPU: `--device mps`. For `ray_train.py` add `--workers 1`; `score.py` scores only with `--workers 0`.
    Scoring is fp32 on every device.
  - NVIDIA: `--device cuda` (or `--gpu`) with `--workers N`. AMP is on by default there.
  - CPU: the default for both trainers and for `score.py`.
  - `demo.py` and `tune.py` accept only `mps` or `cpu`.
- **Small machines.** The MPS fallback ladder is a set of flags, never an automatic retry: `--freeze-embeddings`,
  then also `--micro-batch 4 --grad-accum 8`, then `--freeze-encoder` (head-only, labelled weaker). Each Ray worker
  holds about 2.6 GB, so plan for 16 GB or more per worker. `--object-store-gb` sets Ray's object store size.
- **Busy machines.** `latency.py`, `tune.py`, `mps_spike.py` and `compute_checkpoint.py` run a quiet-machine
  preflight (`--min-available-gib`, default `7.0`; `9.0` for `mps_spike.py`). Passing `0` records a busy-machine run, and the report carries a
  banner for it.
- **Offline / air-gapped.** Run `make weights` (or any first fetch) once, then set `HF_HUB_OFFLINE=1`. To build the
  splits from a local copy of the dataset, use `prepare_data.py --data-dir DIR`. The raw folds must still match the
  pinned sha256s.
  <!-- VERIFY: the hub cache location (huggingface_hub's default cache directory, or HF_HOME if set) is library behaviour not configured in this repository -->
- **Checkpoint location.** Final seeds and few-shot checkpoints can live outside the repo root:
  - `make final-scoring FINAL_ROOT=DIR`
  - `make fewshot-scoring FEWSHOT_ROOT=DIR`
  - `latency.py --checkpoint-root DIR`
  - `demo.py --checkpoint-root DIR`
  - `reproduce.py --verify-checkpoints --checkpoint-root DIR`
- **Split variants.** `prepare_data.py --no-include-no-intent --out OTHER_DIR` writes a variant. Consumers read it
  with `--manifest OTHER_DIR/splits.json`. A variant manifest may not change any split's role, path or folds, and
  the protocol gate accepts only the committed manifest.
- **Interpreter.** `make test` runs in the active interpreter. Use `make test PYTHON=.venv/bin/python` (or any
  target with `PYTHON=...`) to pick the venv without activating it.
- **Live training metrics.** `--tensorboard DIR` on either trainer is off by default and is not part of the run id.
  DIR must be gitignored inside the repo (`tensorboard/`) and must not be under `results/`, `data/`, `ui/`,
  `protocol.json`, `--storage` or `--out`. With the flag on, the run record's timing fields include the logging
  overhead.
