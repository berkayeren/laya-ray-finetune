## Project

**Laya Turkish Banking Intent Pilot**

A pilot that decides whether Laya (`laya-multilingual`) is good enough for Turkish banking intent classification at a bank. It uses the Turkish banking split of Multi3NLU++ (48 multi-label intent tags, CC-BY 4.0) as a public stand-in until the bank's own customer messages can be used. The deliverable is a defensible, reproducible go/no-go recommendation. It compares fine-tuned Laya against a well-known baseline (fine-tuned BERTurk) on accuracy, speed and confidence quality.

**Core Value:** A trustworthy, reproducible head-to-head comparison (fine-tuned Laya vs fine-tuned BERTurk vs zero-shot Laya vs majority) on the full test set. It has to be trustworthy enough to make a go/no-go call that humans can audit and override.

### Constraints

- **Hardware**: Apple M4 Mac with 16 GB unified memory, PyTorch MPS, no CUDA. Fall back to `--freeze-encoder` only if a full fine-tune OOMs, and label that run as weaker.
- **Data**: no real customer data, and no bank name anywhere in the repo.
- **Hosting**: everything runs self-hosted and locally. Hub downloads of public model weights are fine. Any exception needs the user's explicit confirmation. The only one ever considered was a Kaggle GPU training contingency, which the MPS feasibility spike made unnecessary.
- **Reproducibility**: pinned dependencies, recorded seeds and configs, thresholds never tuned on test.
- **Laya internals**: the private API usage must be confined to one adapter module.

## Conventions

## Naming and Style

- snake_case modules and functions, short verbs (`to_case`, `metrics`, `fetch`, `verify_split_file`); UPPER_CASE module constants (`INTENTS`, `QUESTIONS`, `SPLITS`, `TRAINED_ON`); Ray callback `train_loop_per_worker`.
- Terse local names are normal: `a` (parsed args), `c` (train config), `cfg` (model config), `tok`, `mb`, `tp/fp/fn`, `g/p`.
- Every function and method carries parameter and return type hints: Python 3.12 builtin generics (`list[str]`, `dict[str, Any]`, `tuple[int, ...]`), `X | None`, and `typing.Any` where the precise type would need an import the module must not make (never a heavy runtime import for an annotation in a torch-free or numpy-free module). The only production class is `Predictor` in `score.py` (a Ray Data actor).
- PEP 8-like, 4-space indent, double quotes, lines up to ~120 characters, hand-formatted. Compact style: tuple-unpack counters, conditional expressions.
- `%`-style formatting for messages (`"%s: %d messages" % (...)`).

## Error Handling

- Refusals are `raise SystemExit("<what is wrong>; <how to fix>")` with %-formatted messages, raised before any model load or `ray.init` where possible (tampered, unregistered, missing or wrong-role splits; stale manifests; unpinned or mismatched weights). Argument errors use `ap.error(...)`.
- Zero-division is guarded with conditional expressions (`_prf` in `pilot/metrics.py`). try/except is rare (e.g. `write_atomic` cleans up its temp file and re-raises).

## Logging and Comments

- Progress goes through `print` (`flush=True` inside Ray workers; only rank 0 prints in `ray_train.py`). Reports print as `json.dumps(report, ensure_ascii=False, indent=2)`.
- Every script and `pilot/` module opens with a docstring (purpose, design notes, `usage:`). Inline comments explain the "why" of invariants. Helpers that encode a contract carry a docstring stating it and the return value.

## Data and I/O

- Open files with `with` and `encoding="utf-8"`; write JSON with `ensure_ascii=False`. Outputs are written atomically (`pilot.data.write_atomic`).
- JSONL in Laya's training schema, one case per line; parse split bytes with `pilot.data.parse_jsonl` (splits on `\n` only).
- Seeds are explicit (`random.Random(seed)`); `score.py` shuffles with a fixed seed of 0 before `--n`; the bootstrap seed defaults to 0.
- Reports and checkpoints carry repo-relative paths and sha256s, never local paths (`pilot.data.repo_relpath`).
- Frozen records stay byte for byte: `protocol.json`, every `.json`, `.npz` and `.svg` under `results/`, and `data/`. A code constant whose text a committed record holds stays byte-identical; markdown renders and the README's generated blocks are regenerated, never hand-edited.

## Pattern Overview

- Each of the 48 tags is one Laya `noul` question; one forward pass yields a probability per tag.
- Splits: `selection_train` (folds 0-13), `val` (14-15), `final_train` (0-15), `test` (16-19), `hotels_probe` (HOTELS 0-19, out-of-domain). Fold boundaries live only in `pilot.data.SPLITS`.
- The committed `data/splits.json` registers each split's path, role, folds and sha256. Consumers verify the exact bytes they parse; a `--manifest` may differ only in what `prepare()` varies, never in roles, paths or folds.
- `score.py` scores only `val`, `test` and `hotels_probe` (a fine-tuned checkpoint on test or HOTELS only through the protocol gate; a few-shot checkpoint on test only); `ray_train.py` trains only on role `train`. θ is selected on val only (`report.py`), never tuned on test.

## Architectural Constraints

- **DDP invariants:** same seed and items on every rank, equal-sized shards (remainder dropped), `model.no_sync()` on non-step micro-batches, every rank attaches its `rng-rank<r>.pt` to each epoch checkpoint (rank 0 adds `train_state.pt` and `save.json`; resume reads every rank's file), and the final checkpoint (rank 0, `final.json`) is uncalibrated (T = 1) unless `--postfit` stamps the val-fitted T; uncalibrated epoch exports go to `exports/epoch-NNN`.
- **Val-only selection:** Laya's epoch, temperature and θ are chosen on val only (`postfit.py`, which refuses test input), at one encoder LR (2e-05, fixed, not tuned); on test and HOTELS `score.py` admits only the frozen protocol's final seeds, once, and on test only the few-shot checkpoints of the committed runs manifest, once.
- **BERTurk baseline:** BERTurk's epoch, T and θ are val-only too, through `pilot.postfit` (`protocol("berturk")`); both models share the encoder LR 2e-05 (fixed, not tuned) and the head LR 1e-4. BERTurk's epoch grid is 30 against Laya's 4 (and the approved `berturk_epochs` 10), and BERTurk had three selection runs against Laya's one (two recipe changes after a val outcome, the reference-check fixes): a disclosed deviation, rendered in the README from the records. A superseded run (`pilot.berturk.SUPERSEDED`, `results/superseded/`) is never current and can never gate a final seed. No fine-tuned checkpoint of either model was scored on test before the final scoring; since then only the final seeds and (on test only) the listed few-shot checkpoints, once each, behind the protocol gate.
- **Confidence and latency:** the val calibration, abstention and false-positive numbers are in-sample (T, θ and the epoch were chosen on the same val messages); every record carries the caveat and both temperature variants. T and θ come only from val or the postfit record (`report.confidence_binding`; a final seed's record must have been fitted on banking val content, `report.refuse_held_out_record`), never from test or HOTELS; a val split holding committed test, HOTELS or selection_train content is refused as their source, keyed on the content whatever the manifest says (`report.refuse_held_out_theta`; it and the final-seed check below fail closed while a committed split file is missing, `pilot.data.require_committed_files`, which also makes score.py's protocol-gate trigger fail closed), and a final seed is never reported on val or on content it trained on, in any report mode: `report.py RUN_DIR` (so `evaluate.py`), `--compare` and `--confidence` (`report.refuse_final_seed_training_content`); an `ood_probe` dump never reaches `select_theta`. There is one message-confidence rule (`pilot.metrics.CONFIDENCE_RULE`, the joint decision probability), fixed on principle, its val sensitivity disclosed (`report.CONFIDENCE_DISCLOSURE`) and frozen in the protocol. Latency is reported, not gated. The hygiene tests keep every HOTELS dump and fine-tuned test dump the protocol does not open out of git.
- **Frozen protocol and verdict:** `protocol.json` was frozen and hash-pinned (`pilot.protocol.PROTOCOL_SHA256`) before any fine-tuned model was scored on test or HOTELS, and it is never rewritten; `score.py`, `report.py --verdict` and `fewshot.py` call `pilot.protocol.require_frozen` first and refuse a missing or changed file. `score.py`'s protocol gate admits only the six final seeds, once per gated split, and the few-shot checkpoints listed in `results/fewshot/runs.json`, on test only, once, on MPS, fp32, in-process, never with `--force`, `--n` or another `--out-root`. The verdict is computed mechanically (`pilot.verdict` via `report.py --verdict`) from the frozen thresholds and is reported exactly as rendered (INCONCLUSIVE counts as NO-GO; collect bank data). The gated dumps and `results/final/` are the audit record: never rescored or edited by hand.
- **Few-shot experiment:** the frozen protocol's few-shot block was executed unchanged. Every few-shot command (both trainers' `--fewshot-*` modes and every `fewshot.py` mode) calls `pilot.protocol.require_frozen` first and is bound to the frozen recipe by refusal (`pilot.fewshot.check_base`, `check_continued`), never by transcription; the support and replay rows come from the frozen uid lists, never a regeneration, and each masked base's held-out tags are proven absent from its training (the masking proof in its run record). The runs manifest `results/fewshot/runs.json` was committed alone before any few-shot test dump, and every few-shot checkpoint it lists was scored once through `score.py`'s protocol gate, on test only (each masked base also on val, ungated: its θ source), then pruned: the few-shot dumps are the audit record, never rescored. θ comes only from each masked base's own val dump, and the primary metric, new-tag average precision, needs no θ or T. The verdict was rebuilt with the few-shot record (`report.py --verdict --fewshot`): the few-shot path of (d) resolves, and the verdict stays the output of the frozen rule. Caveats the recommendation carries: BERTurk's new-tag micro-F1 is zero on every continued run (its new-tag scores stay below its masked base's val θ; AP is threshold-free and the primary metric); epoch parity, not step parity (step parity is deferred, disclosed); the frozen rule order fires rule 4 on (a) INCONCLUSIVE before any rule that reads (d), so (d) cannot change the verdict while (a) is INCONCLUSIVE (and rule 2, the alternative GO, fires before rule 3, (a) FAIL); θ is never re-selected (each masked base's own val θ; the GO block's seed-averaged systems use each postfit record's `theta.shipped`); Laya's neg8 items against BERTurk's full label rows and the fp16-rounded Laya base a continued run starts from; the descriptive bootstrap; and the bank-name human review, deferred to the milestone end.
- **One-command reproduction and recommendation:** done is decided by committed, hash-verified artifacts only (`pilot.reproduce.plan`: the records and dumps under `data/` and `results/` through their readers and the protocol.json pins, never a checkpoint, Ray storage or run dir), so `make reproduce` on a finished tree skips every step and only regenerates the report. Eval-only (`make report`) never trains or scores (no score.py, training script, `--force` or scoring target) and fails on any rebuilt file under results/, README.md or protocol.json that differs from the committed one. Full mode stops at the first failing command or the first divergence from the frozen record (an output that differs from git HEAD or a protocol pin), states the retraining disclosure (MPS retraining is not bit-identical) before the first model step, never reruns a gated scoring step whose dumps exist and never weakens the gate. The recommendation and the memo are mechanical renders of the frozen verdict (`pilot.memo`, behind `require_frozen` and `check_record`) with no number of their own; humans audit and override outside the repo.
- **Local demo:** `demo.py` binds 127.0.0.1 only (no host flag; `TrustedHostMiddleware` refuses another Host header), stores and logs no message text (uvicorn's access log off, no handler prints a body), is read-only over the committed records (the verdict, selection, latency and few-shot views behind `require_frozen`, `check_record` or a protocol.json pin; no pin covers the confidence records or their reliability SVGs, so the confidence view checks only each record's schema, run id and split against its SVG's name and `GET /api/svg/<name>` serves the file's bytes from disk unhashed; nothing written under `results/`, `data/` or `protocol.json`), has no gate path (it never calls `score.main`, so it never scores into `results/dumps` and never reaches or weakens the protocol gate) and imports no Ray module. Chat answers are not evaluation results, even for a message copied from the test split.
- **TensorBoard logging:** `--tensorboard DIR` is opt-in and off by default. It is `NOT_IDENTITY` in both trainers and kept out of every checkpoint config and record (a CPU run with the flag keeps the run id and byte-identical weights), Laya writes from rank 0 only, and the event files hold the fixed tags and numbers only (no message text, uid or label; comet off). DIR is never under `results/`, `data/`, `ui/`, `protocol.json`, `--storage` or `--out` (judged by realpath and file identity), and inside the repo only where git ignores it (`tensorboard/`). With the flag off the training path is unchanged; with it on, the run record's timing fields include the logging overhead (a per-step device sync for the gradient norm, the memory queries, the event writes), so timings are compared from flag-off runs only.
- **Single node:** `ray_train.py` refuses a multi-node Ray cluster.
- **Laya internals:** private API use is confined to `pilot/laya_adapter.py` (an AST guard in `tests/test_laya_adapter.py` fails on any other importer).
- **Global state:** module-level constants only (`INTENTS`, `QUESTIONS`, `SPLITS`, `TRAINED_ON`, pins).
